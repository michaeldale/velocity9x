# Radeon 9200SE and 9250 (RV280): two surveys, no row

Date: 2026-11-13
Status: **surveys only; nothing claims these cards.** Both run on the
`vbe` package today. A VOGONS user sent two `V9XSURV /rom` files and asks
for the cards to be supported, because ATI's own drivers for them need
Windows 98 or later (their claim, not checked). They also say the `vbe`
driver "doesn't work very well" on these cards, with no symptom, version
or file. No RV280 card is on any of our machines.

Source: [VOGONS post](https://www.vogons.org/viewtopic.php?p=1456614#p1456614),
`Radeon_9200SE.ini` and `Radeon_9250.ini`, `V9XSURV` build `73df075b`,
dated 2026-11-12. The files are the reporter's and are not copied into
the repository; the values below are read from them.

## What the surveys show

Both cards were surveyed in the same machine: a Pentium III Coppermine
(CPUID `00000686`), VIA PM133 north bridge (`1106:0605`) with its AGP
bridge (`1106:8605`), VT82C686 south bridge, 512 MiB, DOS 7.10. The EDID
is the same in both files, a CRT with ranges 30-54 kHz and 50-120 Hz.

| Field | 9200SE | 9250 |
|---|---|---|
| PCI id, revision | `1002:5964`, rev 01 | `1002:5960`, rev 01 |
| Subsystem | `1019:4C43` (ECS) | `148C:2094` (PowerColor) |
| Second function | `1002:5D44`, class `038000` | `1002:5940`, class `038000` |
| BAR0 | `D0000008`: 32-bit prefetchable VRAM | same |
| BAR1 | I/O `C000` | same |
| BAR2 | `E5000000`: registers | same |
| Video BIOS | 48 KiB, `VER008.015.058`, 2003-11-10, `RADEON 9200SE Fab12` | 52 KiB, `VER008.017D.016`, 2004-08-02, `Radeon 9250` |
| VBE | 2.0, `ATI RADEON 9200`, product `V280`, 256 x 64 KiB reported | same |
| VBE modes | 56, 50 with a linear frame buffer at `D0000000` | same list |

- **VBE 2.0**, so no CRTC-information block: the `vbe` package cannot
  choose a refresh rate on these cards.
- **Linear modes** run from 320x200 to 1280x1024 at 8, 15, 16, 24 and
  32 bpp. No 1152x864 and no 1600x1200 in the list.
- **16 MiB reported** by both. A 9200SE or 9250 normally carries 64 or
  128 MiB. The Redwood survey ([`2026-11-07-redwood-row-unmeasured.md`](2026-11-07-redwood-row-unmeasured.md))
  also reported 256 x 64 KiB, so an ATI BIOS cap on the VBE figure is
  the likely reading. `V9XSURV` does not size BARs, so the cards' real
  memory is not known from these files. If the `vbe` package sizes its
  heap from VBE, these cards get 16 MiB; not checked.
- **`Chipset.ATI` reads `unsupported`, `io-base-derived-from-rom-table`.**
  That probe is the Mach64-era one and the survey only queries; it is
  not a fault.
- **The second function** is the second head. Windows may offer it as a
  display device of its own; whether our INF leaves it unclaimed and what
  Windows 95 does with it was not checked.

## Where an RV280 row would sit

In the `ati` family (one family per vendor). Read from the RS690 plan
([`../plans/ati-rs690-x1200.md`](../plans/ati-rs690-x1200.md)) and the
tree; nothing below is measured.

- **2D engine:** the RS690 row drives the legacy Radeon 2D register file
  (`DP_GUI_MASTER_CNTL` 146Ch, `DST_PITCH_OFFSET` 142Ch,
  `SRC_PITCH_OFFSET` 1428h, `RB2D_DSTCACHE_CTLSTAT` 342Ch). Linux uses
  `r100_copy_blit` for R100 through RS690, so DirectDraw fill and copy
  are the part most likely to carry over.
- **Display:** pre-AVIVO, the legacy CRTC block (`CRTC_OFFSET` and
  friends), not the `D1GRPH` registers the RS690 code writes. Flips and
  vblank would be new.
- **3D:** R200, not the R300-class core RS690 has. Direct3D would be a
  new engine; the reference is Mesa's classic `r200` driver.
