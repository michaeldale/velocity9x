# RS690 flips on the AVIVO controller D1

Machine: M-GB8KRE (Sempron 210U, Radeon X1200 IGP 1002:791F, Win98 SE).
Build: branch `ati-rs690` at 13103c2d plus uncommitted work
(`13103c2d-dirty`), all three binaries from one `run-checks` build. The
mini-VDD is byte-identical to the A2 image of
`docs/issues/2026-11-04-rs690-ati-build-black-screen-at-boot.md` (fixed
8-character id). Boot 56, 2026-11-05 ~11:42Z. Captures in
`docs/probe/rs690-flips-2026-11-05/`.

## Before

With the 2D engine claimed and no flip support (boot 52), V9XDDP read
`FlipHr=0`, `Flip20Ms=0`, `FlipMaxMs=0`: the flip went to the VGA CRTC
start address, which the AVIVO controller does not scan from, so DirectDraw
was told it flipped while the screen did not move.

## Change

`src/display32/engines/rs690_scanout.c`, after Linux `rs600_page_flip`:
`D1GRPH_UPDATE_LOCK` set, `D1GRPH_FLIP_CONTROL` 0 (take at the vertical
blank), secondary and primary surface address written, wait for
`SURFACE_UPDATE_PENDING` to rise, lock dropped. Pending until that bit
clears. The address is the frame buffer's GPU base (`HDP_FB_LOCATION`) plus
the surface's offset (`v9x_rs690_scanout_address`, host-tested), after the
2D engine has gone idle. `rs690_hw16.c` stamps `V9X_DD_ENGINE_CAP_FLIP`.

## Measured

- `V9XHW.INI`: `EngineCaps=00000007` (fill, copy, flip).
- V9XDDP (0.34.0 copy): `Result=COMPLETE`, `FlipHr=0`, `Flip20Ms=328`,
  `FlipMaxMs=17`. 20 flips at 16.4 ms each: each waits for a 60 Hz blank,
  where before they took no time. Fill, copy and the four overlap copies
  still `PixelOk=1`.
- `FlipPixelOk=0`, as expected and not a verdict: it reads the screen back
  through GDI, which sees a fixed page once flips are real
  (`docs/issues/2026-09-02-flippixelok-is-uninterpretable.md`).
- V9XTRACE snapshot from the same build (`V9XSNAP.INI`, `BuildsAgree=1`):
  `FlipHandled=23`, `FlipTakenAtDone=23`, `FlipNotTakenAtDone=0`,
  `FlipDeclined=0`, engine FIFO and idle timeouts 0. The controller cleared
  the pending bit for every flip the state machine called done.
  `FlipStillDrawing=107690` is DirectDraw polling GetFlipStatus while a flip
  waits for its blank.

## Not checked

- Nobody looked at the monitor. The counters say D1 took each address; that
  the right page appeared is inferred, not seen.
- The 256-byte address alignment is Evergreen's rule, taken without an
  AVIVO register guide. Every surface V9XDDP flipped satisfied it.
- Only the desktop mode at boot (640x480, 16 bpp) was flipped. Other modes,
  and a game, are next.
