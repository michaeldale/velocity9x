## What the checks turned up

- **The HD 4600's first Glide run failed to open** ("device: no render
  interface"). My earlier copy of the package's GLIDE2X.DLL had not
  landed: SYSTEM still held the 0.19.0 build `a48176ae-dirty`
  (83,968 bytes), which asks for an older render-interface ABI. With the
  package's DLL (84,992 bytes) the probe passes all checks on all three
  machines. So a 0.19-era Glide DLL left in SYSTEM fails against this
  HAL; the package installs its own, so only a hand-swapped machine
  would see it.
- **Half-Life on the Rage 128 is slower than in 0.28.0** (32-34 fps
  then, on the AGP-ring build). It is not this release's code: the
  5dcbdb32 files on the same machine and the same new RAM give 24.6 /
  16.2 fps (boot 640) against `cdbf4cb6`'s 24.4 / 15.8. The CCE has been
  fed by PIO since the ring was parked (07832fde), and that is slower.
- **HD 4600 frames, looked at.** Half-Life Direct3D windowed, playing
  mwd5 at normal speed on this build: the six game frames captured
  (Xen's islands, the beam weapon, the cave) are drawn whole. Walls,
  textures, HUD and effects are present, and nothing is back-to-front
  or missing, which is how the Rage 128's reversed cull showed. This is
  the first time frames, not readbacks, were checked for the indexed
  path, the hardware cull, the guard band and two stages.
- **Diablo II's click path probably ran one screen out of step** and
  hit "Exit Diablo II" (the risk its notes record): its exit is orderly
  and no window remained. So town was not confirmed; title and menus
  drew with nothing refused.
