# GT218: Direct3D's programs and vertices on the Tesla 3D engine

Date: 2026-11-14

Step 5a of [docs/plans/nvidia-gt218-3d-z.md](../plans/nvidia-gt218-3d-z.md):
the builders the HAL will draw with (`src/chipsets/nvidia/gt218/nv50_d3d.c`),
measured by the channel probe's `/3d:d3d` stage before any HAL code
depends on them. M-BXMFA8 (GeForce 210, GT218 A8), boots 118 and 119,
probe built from 84c33dda with the working tree's changes. Evidence:
`build/driver-results/m-bxmfa8-gt218-3d/d1-V9XN5CH.INI` to
`d6-V9XN5CH.INI`.

## What the stage draws

Into a 128x72 X8R8G8B8 pitch-linear surface prefilled with a pattern,
four rectangles, two triangles each, one kick each, in Direct3D's vertex
terms (half a pixel added to sx and sy by the builder):

- A: untextured, solid red, rhw 0.5 at every vertex.
- B: REPLACE, a 4x4 texture of 16 distinct texels, nearest, rhw 1.
- C: MODULATE with specular and fog (the 12th program variant), specular
  alpha 0, so all fog; rhw 1 left, 0.5 right.
- D: REPLACE with rhw 1 on the left and 0.25 on the right.

## Final run (`d6`, boot 119): every check passes

| Check | Matching | Wrong |
| --- | --- | --- |
| A, red within one step | 960 | 0 |
| B, each pixel its texel exactly | 960 | 0 |
| C, the fog colour within one step | 960 | 0 |
| D, perspective-correct texel, off texel edges and the diagonal | 804 | 0 |
| Pattern outside the rectangles | 5376 | 0 |

D's 156 edge pixels are not judged. Of D's pixels, 257 would also fit
affine interpolation, so the interpolation is perspective-correct, not
affine.

## What the runs found, in order

1. **Short instructions must come in pairs** (`d1`, `d2`). Draw C
   trapped with `PGRAPH_INTR` 200000h, trap 80h (MP). The MP's own words
   (nouveau `nv50_gr_mp_trap`, read windows added to the probe VxD) said
   INVALID_OPCODE at fragment offset D54h. The opcode registers showed the
   short `interp $r15 v[0x2c]` before it and B1000015h, the first word of
   the long `fadd` after it: the long instruction began half-way through a
   64-bit word. EXA's programs keep their short instructions paired by
   hand. The encoder (`nv50_shader.c`) now puts a short `mov $r0, $r0`
   before a long instruction that would start on an odd word. The host test
   holds it, and EXA's programs still encode word for word.

   Between `d1` and `d2` the fog constants also moved from `c2[]` to
   `c0[]`: the setup binds buffer 2 to the fragment program's slot 0
   (`SET_PROGRAM_CB` 31h | 2 << 12, as Mesa does). `d2` still trapped, so
   that change did not cause the trap. C's exact fog colour from `d3` on
   shows `c0[]` reads the buffer. Whether `c2[]` would also have read it
   was not tried.

2. **No divide by w with the viewport transform off** (`d3`). The
   builder sent (sx w, sy w, sz w, w). A, at w 2, matched in exactly the
   345 pixels where a rectangle at twice its coordinates overlaps the
   expected one: the engine took x and y as given. The builder now sends
   x, y and z as they are.

3. **The varyings start at `v[0x4]`, w at `v[0x0]`** (`d3`). B's texture
   read texel (0, 0) everywhere. The fragment programs read w at `v[0x0c]`
   and diffuse from `v[0x10]`, a misreading of Mesa's slot code. EXA's
   PFP_C and phase 3's Gouraud program, which ran, read w at `v[0x0]` and
   the first varying at `v[0x4]`. With that layout, A, B and C pass
   (`d4`).

4. **The fourth position word is the weight itself** (`d4`, `d5`).
   Sent 1/rhw, D's texels followed weights of w, not rhw: at x 67 it read
   column 1, which weights of w predict (u 0.257). Perspective and affine
   both give column 0. The builder now sends rhw (`d5`).

5. **The test's own model was wrong** (`d5`, `d6`). `d5` failed 350 of
   D's pixels in v, not u. The quad is not a projected rectangle: v/w is
   not planar across it, so each triangle interpolates v differently. The
   first model took v as linear in y. Recomputed per triangle, every
   judged pixel matches (`d6`).

## Not measured

- 16 bpp targets, blending, the alpha test, the colour mask, the
  scissor narrower than the target, and textures in 565, 1555 and 4444
  are built, but no run drew them.
- Specular's addition is untested: C's specular colour was 0.
- How the engine rounds a perspective-interpolated 1.0 (the one-step
  tolerance on A and C covers it).
- Whether `c2[]` reads buffer 2 too.
