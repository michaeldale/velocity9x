# GMA 950 on the 0.19.0 package: installs by Have Disk, no probe check lost, Half-Life 46.0 and 20.8 fps

Date: 2026-10-18. Machine: MICHAEL-NETBOOK (945GSE / GMA 950), on
ethernet at 10.0.1.248, boots 205-207. The `intel-gma` package of
`d6379b14`'s tree. Evidence:
[`../probe/netbook-gma950-0.19.0-2026-10-18/`](../probe/netbook-gma950-0.19.0-2026-10-18/).

Why: 0.19.0's `intel-gma` driver, mini-VDD and HAL changed for the HD
4600 in code the GMA 950 also runs. That code is the family hw16 hooks,
the Gen3 scanout's entry points, `modes16.c`, the mini-VDD loader and the
Direct3D core. Every Haswell branch reads as guarded, but nothing had
run on the GMA 950 since boot 204's build.

## The install

- **Have Disk:** through Device Manager on the Velocity9x GMA 950
  (function 0), driven by the agent. It pointed at `C:\V9XPKG` and offered
  "Velocity9x Intel GMA 950 (945GSE)" alone.
- **Queued renames:** `glide2x.dll`, `glide3x.dll` and `v9xdisp.drv`. No
  `NUL=` lines.
- **Restart:** Windows' restart was declined, and the agent's `reset`
  restarted the machine instead (the netbook's NDIS2 rule).
- **Boot 206:** all ten files the INF copies match the package by
  SHA-256.
  - The desktop came up at 1024x576 on the panel.
  - `V9XHW.INI` reads `Direct3D=hardware-gen3` and
    `Acceleration=directdraw-fill-blt`.
