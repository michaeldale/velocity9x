# RS690: Direct3D vertex fog in the fragment shader, three ALU instructions

Date: 2026-11-05. Machine: M-GB8KRE (RS690 1002:791F, Win98 SE).
Build: branch `ati-rs690`, 42cfea26-dirty. Captures:
`docs/probe/rs690-fog-2026-11-05/`.

## Decision

The HAL fogs instead of refusing a fogged draw. It is Direct3D's vertex
fog:

- RGB becomes f × colour + (1 − f) × fog colour, where f is the
  interpolated specular alpha and 1 means no fog.
- Alpha is left alone.
- Table fog arrives as vertex fog, because the core writes the table's
  factor into each vertex's specular alpha (`d3d_fog.h`).

The HAL now publishes FOGVERTEX and FOGTABLE.

`v9x_rs690_build_3d_state` with `fog` set appends two ALU instructions
to the one-instruction combine. The fog colour goes in shader constant 0
as R300 float24. The specular colour is routed into its temp even when
specular is off, because fog needs its alpha.

| # | Does |
|---|---|
| 0 | the texture combine and specular add as before, written to a result temp (the one after the specular temp) instead of the output |
| 1 | result.rgb = result.rgb − constant 0, unclamped (MOD_C negate) |
| 2 | out.rgb = result.rgb × f + constant 0, clamped; out.a = result.a |

`US_CODE_OFFSET` takes the instruction count, `US_CODE_ADDR_3` the count
less one, as the X driver writes them. The register list grows from 100
to 128 entries: textured with specular and fog, the state passes 100.

## What the probe measured

V9XRS3D, at 640x480x16 and 1024x768x32. Every older test still passes at
both depths. New tests:

| Test | What | Result |
|---|---|---|
| TlSpecularOnly | untextured specular 00FF00h on red: yellow | exact, both depths |
| TlFogFull, TexFogFull | f = 0: the fog colour whatever is underneath | exact |
| FogInstConst / Factor / Temp | output instruction replaced: constant 0, f, the result temp | exact |
| TlFog | red, f from 1 at the left to 0 at the right, blue fog | within 0.73 step (16 bpp), 0.51 (32 bpp) |
| TlFogSpecular | the same with specular green 64 added first | within 0.86 and 0.51 step |

## What the evidence killed

1. **The presubtract form.** The first build used two instructions:
   out = SRCP × f + fog, with SRCP = src1 − src0 (radeon_reg.h's
   `SRCP_OP`, which Linux's older `r300_reg.h` does not name).
   - With the result written back into temp 0, TlFog passed, but
     TlFogSpecular lost the specular add.
   - With a fresh result temp, red read 0 at both depths.
   - A plain move from that same temp read red correctly.

   Taking the presubtract of a temp that the previous instruction wrote
   gives wrong components on this chip. Why was not pinned down. The
   three-instruction form avoids it.
2. **SRC2_AAA reads the RGB unit's source 2.** It does not: it reads the
   alpha unit's source 2, `US_ALU_ALPHA_ADDR`'s ADDR2. With that left at
   temp 0, f read as the diffuse alpha, 1. The full-fog tests drew the
   unfogged colour, and FogInstFactor read white. The X driver's YUV
   program says the same in a comment ("need to set up alpha source for
   rgb usage").
3. **Colour 1 does not reach the shader untextured.** TlSpecularOnly is
   exact, so it does. This was the first guess from the constant-red
   output, and it was wrong.

## Through the HAL

Boot 72, HAL with fog mapped. V9XD32 passed two runs at 32 bpp and one at
`/bpp16`, each with Failures 0 and T15 clean. The snapshot
(`fog72-snap.INI`) shows 4767 hardware draws, 0 refused.

V9XD32's fog tests need DirectX 7 and 8 render states, which this
machine's DirectX 6.1 runtime does not reach. **No fogged draw has gone
through the HAL yet** (`FogTableBatches=0`). The mapping is host-tested
only (`test_d3d_rs690_map.c`).
