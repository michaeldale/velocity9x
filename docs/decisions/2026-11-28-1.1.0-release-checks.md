## What changed since 1.0.0

Every probe verdict compared with `1.0.0-release-checks-2026-11-27`, by machine and check.

- **i5-4570, HD 4600**: no verdict changed.
  - V9XSNA new: LastExit 0x00000000, HwCursor no-engine
- **Netbook, GMA 950**: no verdict changed.
  - V9XSNA new: LastExit 0x00000000
- **M-BXMFA8, Radeon HD 5770 Juniper 1002:68B8 (remote help)**: no verdict changed.
- **M-7V636C, RIVA 128ZX (remote help)**:
  - V9XSNA: LastExit 0x00000000 to 0x88760028
  - V9XD32 bpp16: Failures 0x00000003 to 0x00000001
  - V9XSNA: not a failure. `LastExit` names the last HAL call traced
    before the snapshot; here it is a `GetDriverInfo` query for a GUID
    the HAL declines, which always returns DDERR_CURRENTLYNOTAVAIL
    (`d3d_core.c`, `V9xHalGetDriverInfo`). Which call happens to be last
    differs run to run.
  - V9XD32 bpp16: better, not worse. T22's 32-bit texture creates are
    now refused (524694d7), leaving T21 (the chip's missing mip-level
    blend), known since 1.0.0. GLIDP BlendHalf is also unchanged from
    1.0.0.
- **M-NZHWBR, i3-2105 HD 3000 Sandy Bridge (remote help)**: no verdict changed.
- **M-Z2T02D, GeForce 9500 GT G96 + HD 2500 IGD (remote help, GitHub issue 30)**: not in the 1.0.0 checks; nothing to compare.
  V9XD32's one failure at both depths is T5 (`T5Ok=0`), the 16-bit
  depth precision test: the G96 runs Z24S8 because NV84_3D has no Z16,
  as [2026-11-28-g96-direct3d.md](2026-11-28-g96-direct3d.md) records.
  Every earlier G96 run today shows the same failure.
