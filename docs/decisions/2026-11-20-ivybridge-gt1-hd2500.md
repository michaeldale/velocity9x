# Intel HD Graphics 2500 (Ivy Bridge GT1, 8086:0152): the HD 4000's path with GT1's thread limits

Date: 2026-11-20
Status: **claimed from one DOS survey; shipped in 0.59.0.** Branch
`intel-ivb-gt1`. GitHub issue 29. The owner has since reported 3DMark
2001 SE completing on it: `2026-11-20-hd2500-field-report.md`.

## The survey

`docs\probe\references\asrock-ivb-gt1-hd2500-0152-vgasurv-2026-11-20-a5156b16.ini`,
V9XSURV `/rom` from the 0.58.0 tool, DOS 7.10:

- `8086:0152` rev 09, subsystem `1849:0152` (ASRock); CPU signature
  `306A9` (Ivy Bridge, family 6 model 58).
- BAR0 64-bit at `F7800000`, BAR2 64-bit prefetchable at `E0000000` (where
  VBE puts the LFB), BAR4 I/O at `F000`: the 0162's layout.
- GGC `0241`: 256 MiB stolen, 2 MiB GTT; BDSM `CFA00001` (locked). VBE
  reports 256 MiB.
- Intel's combined Sandy Bridge/Ivy Bridge VBIOS (PCIR id `0102`),
  checksum good. Modes 640x480 to 1920x1440 and 1366x768 at 8, 16 and 32
  bpp; the EDID's preferred mode is 1366x768 (85.5 MHz).
- INT 10h points at `0070:03DC`, into DOS, not the VBIOS: something
  resident hooks it. Not ours; not followed up.

## What GT1 changes

Mesa's device table (`intel_device_info.c`, read here from the audit
copy): `ivb_gt1` has one subslice of six EUs, 36 VS threads and 48 WM
(PS) threads, VS URB entries 32-512; `ivb_gt2` has 128 and 172. The HD
4000 path asked for:

- 3DSTATE_PS DW4: 64 threads (field 63 at 31:24). Over GT1's 48.
- 3DSTATE_VS DW5: the Haswell word `279 << 23`. Gen7's field is 31:25
  (`gen7.xml` bits 185-191; Gen7.5's is 31:23), so Ivy Bridge reads it as
  70 threads, with two reserved bits set. Under GT2's 128, over GT1's 36.
- The VS URB's 64 entries are inside GT1's 32-512; the push constant
  split is Gen7's for both.

## What changed

- The 16-bit side claims `0152` with its own device row
  (`v9x_ivb_hd2500_device`, the 0162's open, forcewake and heap), and the
  INF lists it as an alias of `hd4000-ivb`.
- Shared ABI 2026112001: `V9X_DD_ENGINE.pci_device`, the matched PCI
  device id, stamped by dd16.c. Every engine cap bit was taken, and the
  limits follow the part within Ivy Bridge's engine identity.
- `hsw_3d.c`: `v9x_intel_hsw_3d_set_gt1`. On Ivy Bridge with GT1 set,
  3DSTATE_PS DW4 asks for 48 threads (`2F000401h` with the attribute
  enable) and 3DSTATE_VS DW5 for 36 in Gen7's field (`46000401h`). The HAL
  sets it from `pci_device == 0152`. GT2's and Haswell's words are
  unchanged, which the host test checks.

## Measured

- Host tests: the GT1 PS and VS words, GT2's restored on clearing it, and
  Haswell's untouched with it set.
- `run-checks.ps1`: passes; the INF lists `PCI\VEN_8086&DEV_0152`.
- GMA 950 netbook, release probes on the branch build
  (`e4ef9e52-dirty`), for the ABI change: every probe passes, no verdict
  changed since the 0.58.0 checks. The runner's card read before install
  ran the new V9XTRACE against the old driver and reported
  `Error=abi-mismatch` (`SnapshotAbi=2026111201`), the stamp refusing as
  it should, so its `LastExit` key is absent. Evidence:
  `docs\probe\ivb-gt1-hd2500-2026-11-20\gma950-checks\`.

## Not established

- Anything on an HD 2500. The first run will be the issue 29 machine.
- Ivy Bridge's one texture stage (the HD 4000's Game 1 hang) is kept.
- The HD 4000's own VS word (70 threads, two reserved bits) is left as
  measured; correcting it to Gen7's field is a change for a machine that
  can run it.
- GT1's RP0 clock: read from the chip, as on the HD 4000; not seen.
