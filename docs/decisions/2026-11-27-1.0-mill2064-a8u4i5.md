# Millennium (MGA-2064W) on the 0.61.0 tree: the 2D-side probes pass and the 3D ones are absent, as on the 86Box guest

Date: 2026-11-27. Machine: A8U4I5 (Pentium III 1 GHz, 128 MiB, Windows
98 SE), its Matrox Millennium (MGA-2064W, `102B:0519`, subsystem 0000,
revision 01) in PCI slot 8. Build: the `matrox` package of
`620b48c3-dirty` (the 0.61.0 tree), installed by
`run-release-checks.ps1 -Machine mill2064` (WININIT renames, `reset`,
8 of 8 files hash-checked each time; boots 734 to 737). The ninth card
of the A8U4I5 round; the card last ran on this machine in October
([record](2026-10-09-mga2064w-tier0-first-boot.md)).

## Getting the card onto our driver

Windows bound Microsoft's inbox driver to it (`DXMGA.INF`, `mgapdx64`,
a new class key `Display\0021`). The install had finished (no wizard
open), so the devnode's `Driver` was set back to `DISPLAY\0011`, the
Velocity9x Millennium key, which still names `v9xdisp.drv` and
`v9xmini.vxd`, and the runner's install did the rest. After the first
restart the Plug and Play Monitor wizard was up and stopped the runner;
it was stepped through with ENTER and Finish.

## Release checks

| Check | Result |
|---|---|
| V9XD32 `/bpp16` | `NO-HAL-AT-DEPTH` |
| V9XGLIDP | FAIL at `Open` |
| V9XR3DP | `FAIL-DESCRIBE` |
| V9XGLP | PASS (`CvaResult=FAIL-MISSING` inside it) |
| V9XWPRS | PASS, 3.71 ms DirectDraw / 10.35 ms OpenGL per present |
| V9XFBCMP | PASS |

The same results as the 86Box Millennium guest on 21 November
([record](2026-11-21-1.0-baseline-checks.md)): the chip has no 3D
engine, so there is no Direct3D HAL, no Glide and no render interface.
That record left open whether Glide and the render interface are
meant to be absent on an engineless card; this run does not answer it
either. The driver reported 800x600x16, engine type 7, caps `7h`, no
engine timeouts or resets.

## 3DMark 2000

Not run: it stops with "3DMark requires a DirectX 7 compatible
3D-accelerator", as it should on a card the README lists with no 3D.

## What the screen shows

An agent screenshot (video memory) of the desktop is correct. The OBS
frame of the card's analogue output
(`Y:\MWD\videos\obs\mill2064-desktop-2026-11-27.png`) has the picture
moved about 50 pixels right and cut at the top, and a mark after every
icon label. The ViRGE/DX's frame from the same capture this afternoon
at the same mode is centred and clean. Since video memory is clean, the
cause is after it: the Millennium's mode timing or DAC, or the capture
device's sampling of it. Not separated; nobody looked at the monitor.
