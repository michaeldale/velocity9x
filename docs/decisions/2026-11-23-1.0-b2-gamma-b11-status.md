# B2 and B11: gamma only on the Mach64-class rows, and each package's Status line from its own manifest

Date: 2026-11-23

## Reading (written by hand; the rest of the record is generated)

### B2: the ati gamma hook

`v9x_ati_load_gamma` writes the Mach64 DAC (`DAC_REGS` 04C0h, `DAC_DATA`
04C1h, `DAC_CNTL` 04C4h), and `ddi.c` claimed gamma on every `ati` row
with an engine descriptor
([issue](../issues/2026-11-09-ati-gamma-hook-writes-mach64-dac-on-evergreen.md)).
`V9X_HW16_OPS` gains `gamma_device` (appended): the family names the
devices its hook's table belongs to, and `ddi.c` claims gamma only there.
The `ati` family answers by engine descriptor: the Mobility-M's (the Rage
Pro class) and the Rage IIC's (the Rage II class), which their 27 aliases
share. Every other row now claims no gamma, and `SetDeviceGammaRamp`
fails there, as on `vbe`. A palette writer for the Rage 128 or a DC_LUT
writer for Evergreen and GCN is 1.1 work.

The check took the `ati` driver's `_TEXT` 43 bytes past its 57,344-byte
budget, so the hook's body moved to `src\chipsets\ati\ati_gamma16.c` in
LEAFCODE behind a near stub, as `oland_engine16.c` and `rv515_engine16.c`
did; `_TEXT` is 57,175 bytes. That adds one external symbol,
`v9x_ati_load_gamma_leaf`. (Moving `mode.c` instead failed to link: it
calls the runtime's 32-bit multiply in `_TEXT`.)

Host test `test_gamma_only_where_the_hook_writes_the_dac`
(`tests\host\test_hw16_modes.c`): the test's stub rows now carry
stand-in descriptors by class. Against a check that claims gamma on every
row with a descriptor, the old behaviour, it failed 9 checks; it passes
on the change.

V9XGAMMA on W9QI0DAD, Oland `1002:6610`, 1024x768x32
(`../probe/1.0-b2-gamma-2026-11-23/`):

| | Before (`713bc38a-dirty`, boot 128) | After (`a92e01f3-dirty`, boot 129) |
|---|---|---|
| `SetDeviceGammaRamp` | succeeded (`SetBright=1`) | failed, `SetError=0x32` (not supported) |
| `GetDeviceGammaRamp` | succeeded | failed |
| `DdCaps2` | `0x000A1001` (`PRIMARYGAMMA` set) | `0x00081001` (clear) |
| Driver's `[Velocity9xGamma]` | sets 2, writes 2 (to 04C1h of the Oland's registers) | no set reached the driver (the line is boot 128's) |

GDI's `COLORMGMTCAPS` read 0 both times; DirectDraw's `PRIMARYGAMMA`
followed the driver's claim. Nothing was seen to go wrong from the old
writes; what the Oland has at 04C0h-04C4h was not read. Not run: the
Rage XL (A8U4I5 offline), so the Mach64 rows keep gamma by the host test
and the unchanged hook body only.

The release probes on the B2 build are boot 123's: all pass but V9XD32
T19.

### B11: the package Status line

`scripts\build-active-package.ps1` wrote one literal, "HOST-AUDITED; GUEST
ACTIVATION NOT YET TESTED", into every package's `MANIFEST.TXT`, which
the release README's Tested column reads
([issue](../issues/2026-08-30-package-status-string-is-hardcoded.md)).
Each `family.psd1` now carries `Package.TestedStatus` and
`Package.CheckRecord`; the build writes `Status: <text>. Record:
<records>` and refuses a family without them or with a record that does
not exist. `check-tree.ps1` checks the same, refuses '|' or a line break
(a README table cell), and refuses the old literal coming back. The texts
are the 2026-11-21 baseline and today's records; `sis` and `3dfx` say
they were not booted. The per-card tier (Supported, Experimental,
Recognised) is not in the line: it is Michael's decision 3 in the plan.
`run-checks.ps1` passes; the eight manifests were read after the build.

Status: measured on 1 machines on `a92e01f3-dirty`, built from a dirty tree: a measurement, not a release check. The probes (V9XD32, V9XGLP, V9XGLIDP, V9XR3DP, V9XWPRS, V9XFBCMP) were rebuilt with that build id first. Every probe report's `Build=` line is checked against it below.

Evidence: [`../probe/1.0-b2-gamma-2026-11-23/`](../probe/1.0-b2-gamma-2026-11-23/): the V9XGAMMA and V9XESC reports before and after, and `release/`, one folder per machine. Generated by `scripts/run-release-checks.ps1`.
