# HD 2600 XT: Direct3D through the CP, V9XD32 at 16 bpp passes (mip chains from boot 9)

Date: 2026-11-13

Status: **measured, one card, boots 7, 8 and 9.** M-NZHWBR's HD 2600 XT
(`1002:9588`, RV630) on the `ati` driver built from this commit's tree
(dirty against `020dd1c5`), installed by WININIT renames. The Direct3D
step of [the plan](../plans/ati-rv630-hd2600xt.md), after V9XR63D drew
the builder's streams exactly
([record](2026-11-13-rv630-gouraud-texture-depth.md)). Captures:
[`../probe/rv630-d3d-2026-11-13/`](../probe/rv630-d3d-2026-11-13/).

## What was built

- `engines\r6_cp.c`: the CP in V9XHAL.DLL, V9XR63D's bring-up (microcode
  from `r6_cp_microcode.c`, generated by `gen-r600-microcode.ps1`; ring in
  the EG_MAP window after the DMA ring; `r600_gpu_init`'s table through
  the ring without the two threshold registers), Evergreen's ring, arena
  and drain handling (`eg_cp.c`).
- `d3d\d3d_r6_map.c` (host-tested by `test_d3d_r6_map.c`) and
  `d3d\d3d_r6.c`: Evergreen's mapping and engine on `struct
  v9x_r6_3d_state`.
- `r6_3d.c`: `d3d_order` - the target written SWAP_STD and textures read
  XYZW, so a D3DCOLOR fetched as bytes in memory order is B, G, R, A as on
  Evergreen; RGB565 targets; 565/1555/4444 textures at the 256-byte group
  pitch (128 texels at 16 bits); `texture_opaque` for XRGB8888.
- `r6_shader.c`: the D3D VS (TL vertex, every fetch a mega-fetch, R0
  last) and the NONE/REPLACE/MODULATE PSs with normalised coordinates.
- `eng_r6.c`: waits for the CP before fills and copies and in its idle
  wait; a depth fill short of the whole 1D-tiled Z16 is drawn on the CP.
- The RV630 row stamps `CAP_D3D` (`EngineCaps=00000013`,
  `Direct3D=hardware-r600-cp` in V9XHW.INI); `d3d_select.c` routes engine
  type 15 to the new engine.

## V9XD32 /bpp16 (640x480x16, the row has no 32 bpp modes)

| Check | Boot 7 | Boot 8 (XRGB8888 offered) |
|---|---|---|
| T1 flat, T4 offscreen, T14 child | EXACT | EXACT |
| T2 Gouraud corners, T3 depth, T5 precision, T8 sloped depth | all OK | all OK |
| T6 565 texture (red, green, blue, white) | 0Fh | 0Fh |
| T22A ARGB8888 texture | 0Fh | 0Fh |
| T22X XRGB8888 texture | **0** (black: format not offered, draw refused) | 0Fh |
| T7 blend, T9 indexed cull, T10 guard band, T11 cull matrix | OK | OK |
| T13 volume, T15 sentinels, T16 DX7 | PASS | PASS |
| T20 DX5 states | F200h, expected F000h (alpha test and its lightmap pass) | same |
| T21 mipmaps | **fail**: levels 0-3 all red (`F800`) | same |
| RunIdleTimeouts / RunFifoTimeouts | 0 / 0 | 0 / 0 |
| Failures | 2 | 1 |

So Direct3D's order is right on this card: the 565 and 8888 textures'
colours land in the right channels on a 565 target, and depth through the
HAL agrees with V9XR63D's. The tiled Z buffer reads back FFFFh at the
probe's linear guesses (`ZTiled*`), as it should for a 1D-tiled surface;
T3 and T5 judge depth by the pixels and pass.

T21 fails as expected: no mip chain is placed or sampled; every mip
filter samples level 0. The depth constant of boot 5
([issue](../issues/2026-11-13-rv630-depth-constant-z.md)) did not appear
in either boot.

## Mip chains (boot 9): V9XD32 passes

Chains are now placed in one block in Evergreen's layout
(`v9x_eg_3d_mip_layout`: every level's pitch its width rounded to
MAX(64, 256 / bytes a texel), the levels back to back), which is also
libdrm's `r6_surface_init_linear_aligned` for R6xx, and sampled with
RESOURCE_WORD3 at level 1, WORD5 LAST_LEVEL, SAMPLER_WORD0 MIP_FILTER and
WORD1 MAX_LOD in Mesa r600_state.c's 4.6 fixed point (Evergreen's
measured 4.8 is not R6xx's). V9XD32 /bpp16 on boot 9: T21 levels 0-3
`F800`, `07E0`, `001F`, `FFFF` (red, green, blue, white), `T21Ok=0F`;
every other check as on boot 8; **Failures 0, Result PASS**, no
timeouts. Capture `boot9-V9XD32-bpp16.TXT`.

Only MIPNEAREST was judged (T21's filter). Four quad sizes landing on
four different levels says the LOD scale and the level addresses are
right to the nearest level; trilinear blending is untested.

## Not done, not measured

- Specular and fog: drawn without them and not advertised (T20's fog and
  ADD bits are outside its expectation for that reason). The lit shaders
  are not ported.
- A source colour key: refused, not advertised (TRANSPARENCY off).
- 32 bpp: the row lists no 32 bpp mode, so the XRGB8888 target path is
  host-tested only.
- Any game or benchmark; OpenGL and Glide (no r3d engine id).
- The partial depth fill on the CP: V9XD32's clears were whole-surface.
