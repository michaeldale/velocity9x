# RS690: DirectX 8 on M-GB8KRE, and 3DMark 2000 on the HAL and on software

Date: 2026-11-06. Machine: M-GB8KRE (RS690 1002:791F, Win98 SE).
Boots 80-82. HAL: branch `ati-rs690`, 40f409c5-dirty (the targeted
idle wait, f6ed13f1's code). Captures:
`docs/probe/rs690-3dmark2000-2026-11-06/`.

## DirectX 8.0

The machine had DirectX 6.1, which skipped V9XD32's DirectX 7 tests and
could not run 3DMark 2000. The steps:

- `DX80ENG.EXE` went across by `put` (11.5 MB, 351 s, hash checked).
- It was extracted with `/Q /T:C:\DX8\EX /C`.
- `DXSETUP /silent` returned exit code 1. Its WININIT.INI held about 70
  `NUL=` + rename pairs.
- Michael approved restarting through them. The agent's `reset` came
  back by itself at boot 80.
- WININIT.INI and the `SET*.TMP` files are gone. The DirectX registry
  version is 4.08.00.0400.

V9XD32 at 32 bpp on boot 80 (`d32-dx8-32.txt`): Failures 0, T15 PASS,
T20Ok FFF, T21Ok F.

| Test | Result |
|---|---|
| T16, DirectX 7 device with textures | runs for the first time on this chip and passes (TextureOk F) |
| T18, HAL device against a T&L device | stops at NO-TNL-DEVICE: the RS690 HAL publishes no T&L device |
| T17 and T19 | skip: they call Direct3DCreate8 with the 8.1 SDK version, and this is DirectX 8.0 |

Fog through the HAL had already been drawn by T20 (DX5); T18 adds
nothing here.

## 3DMark 2000 v1.1

Installed from `3DM2K11.EXE` (20 MB, 612 s by `put`, hash checked) to
`C:\Program Files\MadOnion.com\3DMark2000`. The licence was accepted
and registration skipped ("Purchase Later"): the free edition runs
the default benchmark. Run Default Benchmark is at (289, 264) on the
640x480 desktop; the main window's Close/Show Details are on the score
dialog.

| Direct3D | Score | Run time |
|---|---|---|
| Velocity9x HAL on the RS690 (boot 80) | **1781** | about 7 min |
| Software (`[Velocity9x] Direct3D=2`, boot 81) | **7** | about 47 min |

The plan asked whether register writes (PIO) on a 1.5 GHz Sempron beat
the software engine at all. They do, by a wide margin, at 3DMark's
default 1024x768x16. Per-test frame rates were not read.

The HAL snapshot after the run (`3dm-hal-snap.INI`; boot 80 also
includes one V9XD32 run):

| Counter | Value |
|---|---|
| hardware draws | 1,668,375 |
| triangles | 72,565,346 (43.5 a draw) |
| textured draws | 1,502,332 |
| refused / unrenderable | 0 / 0 |
| engine idle timeouts | 0 |
| idle wait's share of draw cycles | 4.6% (46,185,958 of 1,007,623,455 units) |
| draws that waited more than 4096 cycles | 6,136 |
| textures created | 2,528 |
| mip chain levels seen | 1 |

Nothing 3DMark 2000 asked for was refused. Its textures arrived without
mip levels (D3dMipChainLevels 1), so mipmaps are still unproven in an
application. With about 43 triangles a draw, against Rollcage's 8, the
idle wait after 2D is now a small part of draw time.

Boot 82 put SYSTEM.INI back (hash checked, Direct3D=0). V9XD32 then
passed: Failures 0, T20Ok FFF, T21Ok F, T15 PASS.
