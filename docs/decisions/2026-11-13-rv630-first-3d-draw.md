# The HD 2600 XT's first 3D draw: a solid rectangle through the CP, exact

Date: 2026-11-13

Status: **measured, one card, six runs on one boot.** M-NZHWBR's HD 2600
XT (`1002:9588`, RV630), boot 5, the `ati` driver of `2c6eeccb` running
DirectDraw on the DMA engine. The 3D step of
[the plan](../plans/ati-rv630-hd2600xt.md), after the CP ring test
([record](2026-11-13-rv630-cp-ring-test.md)). Tool: `V9XR63D.EXE` on
`EGCP.VXD` (`tools\diag\rv630_3d_win32.c`), with the new pure builders
`src\chipsets\ati\r600\r6_3d.c` and `r6_shader.c`, host-tested by
`tests\host\test_r6_3d.c`. Captures:
[`../probe/rv630-3d-2026-11-13/`](../probe/rv630-3d-2026-11-13/).

## The draw

Ported from xf86-video-ati 6.14.6's R6xx acceleration (`r6xx_accel.c`,
`r600_exa.c`'s solid fill, `r600_shader.c`'s solid VS and PS) and Linux
`r600_gpu_init`'s RV630 configuration, all through the CP:

1. `ME_INITIALIZE`, then Linux's ring test.
2. `r600_gpu_init`'s configuration as `SET_CONFIG_REG` writes (8000h-
   AC00h), read-modify-write from MMIO reads where Linux reads first;
   GB_TILING_CONFIG from RAMCFG (A9h gives 8A12h, the BIOS's value).
3. xf86's default state for the RV630: START_3D_CMDBUF, CONTEXT_CONTROL,
   SQ resource split, DB/CB/PA/SPI/VGT defaults, clip rects and scissors.
4. A 64x8 linear ARGB8888 target, xf86's solid VS/PS with the colour in
   PS constant 0, a three-vertex RECTLIST for [8,56) x [2,6) in
   `FF3366CC`, then cache flush, WAIT_UNTIL 3D idle clean, a CB surface
   sync and a SCRATCH_REG0 marker.
5. Every config register read in call 1 put back through the ring.

## Runs

| Run | Change | Result |
|---|---|---|
| 1, 2 | as built | ME stalled, CP_BUSY alone; RPTR at the draw submission's end; target untouched |
| 3 | stage markers after gpu_init and the default state | neither landed: the stall is inside gpu_init's writes |
| 4 | gpu_init without CP_QUEUE_THRESHOLDS and CP_MEQ_THRESHOLDS | **drawn**: 192 pixels `FF3366CC`, background and guards exact, GUI idle; the put-back (which restored the same two) stalled |
| 5, 6 | the put-back without them too | every stage PASS, 0 mismatches, 0 guard mismatches |

After each stall the probe's GRBM soft reset of the CP blocks left
`GRBM_STATUS` at `3030h` and the CP halted; the next run started clean.

## What it settles

- **The CP must not write its own queue thresholds through its ring.**
  Linux writes `CP_QUEUE_THRESHOLDS` (8760h) and `CP_MEQ_THRESHOLDS`
  (8764h) from `r600_gpu_init`, which `r600_startup` runs before the CP is
  resumed, so by MMIO with the CP halted. Through the ring the ME stalled
  every time. The BIOS leaves them at `2C16h` and `40400000h`; Linux's are
  `2B16h` and `40400000h`. They stay as the BIOS left them.
- The rest of `r600_gpu_init`'s configuration goes through
  `SET_CONFIG_REG` without harm, and the 3D pipeline, the SQ, the VS's
  vertex fetch, the PS's constant and the CB all work as xf86 programs
  them, at linear layout.

## Not measured

- Interpolated colour, depth, blending, textures, triangles other than
  the RECTLIST.
- Anything outside the 64 KiB window, or with DirectDraw drawing at the
  same time.
- The HDP, DCP and DMA tiling copies and ARB_POP Linux also writes
  (outside the ring's reach; this draw is linear).
