The devnode already pointed at Velocity9x's ViRGE/DX key

## Release checks

| Check | Result |
|---|---|
| V9XD32 `/bpp16` | FAIL: T20 (`T20Ok=08A0`), T21 (mip levels), T22A and T22X |
| V9XGLIDP | FAIL at `FogTable` |
| V9XGLP, V9XWPRS, V9XFBCMP | PASS |
| V9XR3DP | COMPLETE |

V9XD32's failures are the 86Box ViRGE/DX guest's of 21 November, key
for key (`Failures=4`, the same `T20Ok`, `T21Ok`, `T22*Ok`). They are
not regressions from November's V9XD32 PASS on this card (boot 666):
T20 and T21 were added to the probe on 6 November and T22 on 11
November. The ViRGE offers only 1555 and 4444 textures (README), so
T22's 32-bit formats have nothing to land on. The FogTable failure is
the known one: the ViRGE claims vertex fog it does not draw.

## 3DMark 2000

The runner's 3DMark step cannot pass 3DMark's 16 MiB default on 4 MiB,
so both runs were by hand (VNC stopped), default tests:

| Setting | Score (recorded, not compared) | Flips | Engine idle timeouts / resets |
|---|---|---|---|
| 640x480x16, 16-bit Z, triple | 152 | 1,505 | **45 / 45** |
| 800x600x16, 16-bit Z, triple (November's setting) | 141 | 1,350 | 0 / 0 |

November's run at 800x600 had no timeout either. So the timeouts come
with 640x480, not with a change since November; where in the run they
fell was not recorded. The Trio3D/2X, on the same S3D path, had 51 in
its only 3DMark 2000 run, also at 640x480
([issue](../issues/2026-11-26-trio3d2x-3dmark2000-engine-timeouts.md)).
Filed ([issue](../issues/2026-11-27-virgedx-3dmark2000-640x480-engine-timeouts.md)).

## 1024x768x32 on a monitor (owed re-run)

`V9XMSW /set:1024x768x32` from 800x600x16: `Result=PASS`,
`ChangeResult=0`. The card's VGA output, captured by OBS through the
capture card (`virgedx-1024x768x32/obs-1024x768x32.png`), shows the
whole desktop at 1024x768, geometry and colours correct, as at
800x600x16 (`obs-800x600x16.png`). XFree86's "not possible, a hardware
limit of ViRGE chips" does not hold for this ViRGE/DX through the VBE
mode set
([issue](../issues/2026-08-30-virge-1024x768x32-xfree86-limit.md),
closed). Set back to 800x600x16 afterwards.
