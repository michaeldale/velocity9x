# 0.19.0 on an emulated Trio64: installs over 0.18.5, no DirectDraw-probe check lost

Date: 2026-10-18. Machine: the 86Box `Win98SE-Trio64` VM (WIN98-S3NATIVE,
`127.0.0.1:9871`), boots 364-366. One probe run on 0.19.0, at Michael's
word ("do upgrade to 0.19 and do single probe run"); no baseline was run
on 0.18.5. Evidence:
[`../probe/86box-trio64-0.19.0-2026-10-18/`](../probe/86box-trio64-0.19.0-2026-10-18/).

Why this card: 86Box emulates neither the GMA 950 nor the HD 4600. The
VM does run the code 0.19.0 changed for every family: the 16-bit runtime,
the mini-VDD loader and the DirectDraw core.

## What was done

1. The agent went from 0.9.0 to 0.11.0 (hot `update`).
2. The VM was on a build older than 0.18.5. The released
   `velocity9x-0.18.5-s3.zip` went on first, then `build\win98se-s3` from
   `d6379b14`'s tree.
3. Each install went through Device Manager's Have Disk, driven through
   the agent, and was followed by Windows' own restart.
4. Each install queued renames only: `v9xdisp.drv` for 0.18.5, then
   `v9xdisp.drv` and `v9xhal.dll` for 0.19.0. No `NUL=` lines.

## Measured on 0.19.0, boot 366

- **Files:** `V9XDISP.DRV`, `V9XMINI.VXD`, `V9XHAL.DLL`, `V9XGL.DLL` and
  `V9XSETP.DLL` in SYSTEM all match the package by SHA-256.
- **V9XMSW `/cycle:3`:** `Result=PASS`, 3 of 3 cycles, starting from
  800x600x16.
- **V9XGDI:** `Result=PASS`. The agent's 300 s exec timeout expired
  first; no window was left afterwards.
- **V9XDDP:** `Result=COMPLETE`.
  - **First pass (`V9XDD.INI`):** every Direct3D call returns
    `0x88760231`. That is the "did not run" state earlier records show on
    the netbook, the ViRGE and Gen3 (2026-10-04 Trio3D record).
  - **16-bit pass (`V9XDD2.INI`):** 83 Ok keys at 1 and 31 at 0.
  - **Against the 2026-09-10 Trio64 record**
    (`probe/software-d3d-sysmem-2026-09-10/trio64-sysmem-allowed.ini`):
    no key that passed then fails in the 16-bit pass now.
    `BlendModulateOk` failed then and passes now.
  - **Not compared:** checks that the old record holds and this run made
    only in its first pass. They are listed in the probe folder by their
    absence from `V9XDD2.INI`. Running the probe on a 16-bit desktop
    would cover them.
  - **`FlipPixelOk=0`** is in every Trio64 record since 2026-09-10, and
    on the ViRGE and the netbook too.
