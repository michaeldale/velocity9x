## The GMA 950's Half-Life runs

Four Half-Life faults on the netbook, none after a console `quit`:

1. Boot 274: the check script's agent `kill` did not match `HL.EXE`, so it
   started the OpenGL run's `hl.exe` while the Direct3D timedemo was still
   playing. The demo stopped at the menu with no result. `WCLOSE` then
   faulted HL at EIP 0 (invalid page fault, module unknown).
2. The next launch, `-d3d`: a stack fault in `KERNEL32.DLL` at
   `018f:bff7429f` before the window appeared.
3. Boot 275 (after `reset`), first launch, `-d3d`: the same fault, same EIP
   and ESP.
4. `-gl` reached the menu; `WCLOSE` at the menu faulted at EIP 0 with the
   same registers as fault 1 (the HAL's fault watch recorded this one).

Then an OpenGL timedemo ended by typing `quit` at HL's console exited
cleanly, and the next `-d3d` launch started, ran mwd5 at 44.4 fps and exited
cleanly the same way.

Reading: `WM_CLOSE` at Half-Life's menu faults HL on this machine, and the
KERNEL32 stack fault on the launches after went away once HL had exited
cleanly once, so it was state left by the faulted close, not the driver.
Not proven: no control run on 0.35.0's files. In 0.35.0's check `WCLOSE`
closed HL after a finished timedemo without a fault.
