# HD 5450 runs 3DMark 2000, once a DMA ring wrap was fixed

Date: 2026-10-27

Status: **measured, one card.** M-BXMFA8's HD 5450 (`1002:68F9`, Cedar),
boots 27 to 31. Follows
[specular and fog](2026-10-27-cedar-specular-and-fog.md). Captures in
[`../probe/m-bxmfa8-cedar-3dmark2000-2026-10-27/`](../probe/m-bxmfa8-cedar-3dmark2000-2026-10-27/).

## The failure (boots 27 to 29)

3DMark 2000 Pro (build 340) was installed on the machine before this
work. Its default benchmark drew Game 1 at low detail: textured terrain,
trees, fog, the helicopter and the HUD (`frame-*.png`, boot 27). About a
minute later it stopped with "3DMark could not initialize your 3D
Accelerator ... CreateDevice : DDERR_GENERIC" (`V9XWND-error.INI`).

- The HAL snapshot (`V9XSNA7-after.INI`) showed `D3dContextRejects=1`, with
  no `D3dTargetLayout` event between that create's entry and its exit.
  The create was refused before the target was examined: there were no
  engine ops, because `EngineFlags=8` had lost `V9X_DD_ENGINE_VALID`.
- `EngineIdleTimeouts=1`, and the fault trace (`V9XTRACE-fault.INI`)
  carried tag `EG2D`: the DMA engine's idle wait had timed out. That wait
  came on a draw right after a depth fill (`Blt 0x02000000`,
  DDBLT_DEPTHFILL) went to the DMA engine. A DMA timeout gives up the
  engine for the mode, and Direct3D goes with it.
- The fault trace names the timeout but not why the engine stopped, so
  `eng_eg.c` now writes `C:\V9XDIAG\V9XEGDMA.TXT` at the first timeout:
  the DMA registers, the CP's pointers and the whole ring. Boot 28
  failed the same way and the record said:

| | Boot 28 |
|---|---|
| our write position | `8000h` bytes |
| `DMA_RB_WPTR` | `00008000` |
| `DMA_RB_RPTR` | `00006E90` |
| `SRBM_STATUS2` | `0` (not busy) |
| `DMA_RB_CNTL` | `1B`: 2^13 dwords, 32 KiB |

The write pointer had been written as the ring's size. The register takes
offsets inside the ring only. The engine stopped at `6E90h` and went idle,
and the wait for its read pointer to reach `8000h` could not end.
`v9x_eg_submit` wrapped to 0 only for a submission that would pass the
end. One that ended exactly at the end left the position at the size,
which takes an exact landing: minutes of 3DMark's per-frame depth fills.
The CP's submit masks its position after every submission; the DMA path
never did.

## The fix

`v9x_eg_dma_ring_advance` (eg_dma.c) gives the position after a padded
submission, wrapped to 0 at the ring's end. The host test was written
first and failed on the two end-of-ring cases, then passed. A submission
that wraps this way also waits for the engine to finish its lap, as the
existing wrap path does: nothing else checks ring space.

Boot 29 still failed. It turned out to be running the boot-28 HAL: the
deployment's WININIT.INI had not been written (`deploy-ati.ps1` was piped
into `Select-Object -First 3`, which stops the script after its third
output). The guest's `V9XHAL.DLL` hash differed from the build, and the
staged files were still in `C:\`. Boot 31 runs the fixed HAL, checked
by hash.

## Boot 31: the default benchmark completes

1024x768, 16-bit colour, triple buffer, 16-bit Z, 16-bit textures, VSync
off. Card "Velocity9x VBE-generic display", V9XHAL.DLL 0.31.00.0000,
16384 KB video memory, 14848 KB texture memory, one texture stage. Screens:
`b31-score.png`, `b31-results-*.png`, `b31-details-*.png`.

| | |
|---|---|
| 3DMark result | **5267** (CPU speed 303) |
| Game 1 Helicopter, low / medium / high | 103.3 / 66.3 / 21.3 fps |
| Game 2 Adventure, low / medium / high | 124.1 / 76.5 / 47.5 fps |
| Fill rate, single / multi texturing | 629.2 / 629.4 Mtexels/s |
| High polygon count, 1 / 4 / 8 lights | 2035 / 1904 / 1828 Ktriangles/s |
| Texture rendering, 8 / 16 / 32 / 64 MB | 561.6 / 497.0 / 345.7 / 42.3 fps |
| Bump mapping | not supported (one texture stage) |

The score is recorded, not compared. 3DMark lists specular Gouraud, vertex,
table and W fog, and trilinear filtering as supported.

The snapshot afterwards (`V9XSNA7-b31-after.INI`): `EngineFlags=9` (valid
and validated), no idle timeouts, five device creations, none refused.

## Open

- The heap is the VBE's 16 MiB on a card with 1 GiB. The 64 MB texture
  test runs at 42 fps against 346 at 32 MB, which looks like textures
  being swapped. A larger heap is a family change (the 16-bit side maps 16 MiB).
- Boot 27's screenshots showed a black rectangle where 3DMark's dialogs
  had been, over the error dialog too. It did not appear on boot 31's.
  Cause unknown.
- Frames were seen only in boot 27's screenshots of Game 1. Boot 31's
  run was not inspected frame by frame.
