# Oland 6611 on M-BXMFA8: a survey, and the 6610's row claims it

Date: 2026-11-20

Status: **claimed from one read-only survey; the ati row passes the
6610's probes on it (boot 185); no game run.** M-BXMFA8
(W9QI3632, Core 2 Duo E7500, AMI BIOS 02/26/10, Win98 SE, agent 0.19.0),
remote help. The owner swapped the Matrox P650 for this card and asked by
chat (2026-11-20 07:55 UTC) for it to be added. Evidence:
[`../probe/m-bxmfa8-oland-6611-survey-2026-11-20/`](../probe/m-bxmfa8-oland-6611-survey-2026-11-20/).

## The card

Read by the agent's `inventory` and `V9XSIMM` (rebuilt from `67150f27`,
read-only), with the released vbe package driving the desktop at
1024x768x32:

| | 6611 (M-BXMFA8) | 6610 (W9QI0DAD, [2026-11-16](2026-11-16-oland-first-survey.md)) |
|---|---|---|
| PCI id | `1002:6611` rev 87, subsystem `1028:1002` (Dell) | `1002:6610` rev 00, subsystem `1028:2120` (Dell) |
| BAR0 | `D000000C`: 64-bit, prefetchable, below 4 GiB | `D000000C`, the same |
| BAR2 | `FEAC0004`: 64-bit, 256 KiB registers | `FDD80004` |
| VRAM | `CONFIG_MEMSIZE` 800h = 2048 MiB, GDDR5 (`MC_SEQ_MISC0` type 5) | 2048 MiB, not GDDR5 (type 11) |
| `CC_GC_SHADER_ARRAY_CONFIG` | FFC00000: six CUs active | FFC00000 |
| `CC_RB_BACKEND_DISABLE` | 0: both RBs | 0 |
| `MC_ARB_RAMCFG` | 2A2h: NOOFCOLS 2, a 4 KiB row | 12A1h: NOOFCOLS 2 |
| `MC_VM_FB_LOCATION` start = `HDP_NONSURFACE_BASE` | yes (`Bar0AtVramStart=yes`) | yes |
| VM L2, contexts 0 and 1 | off | off |
| CP, RLC, DMA0/1 | halted or idle, rings off | the same |

`pci.ids` names 6611 "Oland [Radeon HD 8570 / R5 430 OEM / R7 240/340/430
/ Radeon 520 OEM]", and Linux's amdgpu binds it as CHIP_OLAND with the
6610's flags. On this board it is the full die, not a harvested one.

## What the 6610's row assumes, and what this card shows

`si_gpu_init.c` writes three values from W9QI0DAD's card:
`GB_ADDR_CONFIG`'s row size from `MC_ARB_RAMCFG`'s NOOFCOLS, a raster
config for two RBs, and `SPI_STATIC_THREAD_MGMT_3` with CU 0 as the
lowest active CU. This card reads the same three. The ring window at BAR0
+ 240 MiB needs BAR0 at VRAM's start and 256 MiB of BAR, which it has.
The memory type differs; the VBIOS trains the memory and the driver
writes no memory-controller timing, so it is not an input.

So 6611 is the 6610's alias: a `V9X_HW16_DEVICE` of its own
(`v9x_si_oland_6611_device`, the same tail), the backend's id list, both
of `ati_hw16.c`'s address checks (diagnostics and the 128 MiB heap), the
registry and the INF.

A harvested 6611 (fewer CUs or RBs) would read differently here and is
not covered by this survey: `si_gpu_init.c`'s three constants would then
be wrong for it.

## Cost

The ati family's `_TEXT` went 243 bytes past its 57,344-byte budget with
this row and the RV280 9200's two
([2026-11-20-bus-siblings-claimed-unrun.md](2026-11-20-bus-siblings-claimed-unrun.md)),
since each device row and its strings link into `_TEXT`. `vsync.c` moved
to LEAFCODE, as `d3dmode.c` did, which freed 108 bytes; `resources.c`
followed (nothing in the 16-bit image calls it; the backends that do are
host-built). The family's PCI scan table grew from 48 to 56 ids (the ati
family now declares 49).

## Boot 185: the ati build on the card

The ati package built by `run-checks.ps1` from this tree (`67150f27-dirty`)
went in over the vbe package by WININIT rename: DRV, VXD, HAL, SETP and
the ICD, staged as `C:\V9XSTAG\V9XN1-5.BIN`, hash-checked before and
after; the vbe files are backed up off the machine. `reset -DismissLogon`,
back as boot 185 in about a minute. The class key still names the vbe
package, as on W9QI0DAD's first ati boot. Evidence:
[`boot185-ati/`](../probe/m-bxmfa8-oland-6611-survey-2026-11-20/boot185-ati/).

- V9XHW.INI: `Adapter=AMD Radeon Oland 6611`, `Stage=enable-ok`,
  `OlandEngine=engine`, `OlandBar0=D0000000`, `OlandBar2=FEAC0000`,
  `EngineCaps=40800017`, `Direct3DMode=hardware`, 1024x768x32.
- V9XDDP: `BltFillPixelOk`, `SrcCopyPixelOk`, `KeySrcFillPixelOk` and
  the four `Overlap*PixelOk` are 1. `FlipPixelOk=0`, as in all six of
  the 6610's recorded runs.
- V9XD32 at 32 and 16 bpp: `Failures=0x00000001`, T19 only:
  `FfSpecFog` 17 pixels, the count of every 6610 run
  ([issue](../issues/2026-11-17-t19-ffspecfog-mismatch-oland-gt218.md)).
  T18 reports `NO-TNL-DEVICE`, as the Oland has no T&L device.

So on the probes the 6611 behaves as the 6610 does. No game or 3DMark
has run on it.
