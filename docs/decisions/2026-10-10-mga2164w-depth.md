# The MGA-2164W's depth buffer: as specified, except that it clamps at the top

Date: 2026-10-10. A8U4I5 (10.0.1.172), boot 385, the Millennium II
MGA-2164W (8 MiB) on Velocity9x `matrox` at 800x600x32. Phase 2 of the
[hardware Direct3D plan](../plans/matrox-mga2164w-hardware-3d.md).
Evidence in `docs/probe/a8u4i5-mga2164w-depth-2026-10-10/`.

## The instrument

`MGA2D.EXE /depth` (with `/vram:8`, region at 7 MiB): Gouraud trapezoids
with a Z buffer, built by `mga_3d.c`, which now takes a depth width, a
zmode, ZI or I, a Z buffer offset (from which it derives ZORG) and the Z
interpolants - 17.15 in DR0/DR2/DR3, or 33.15 in the DRn_Z32 LSB/MSB pairs
at 2C50h-2C6Ch for 32-bit Z, with MACCESS.zwidth. Colour bands use the
region's first half and each case's Z rows the second half at the same
row, so one ZORG serves every case: `0x400000` for 16-bit Z and `0x80000`
for 32-bit. Each case prefills its Z rows, draws, reads both the colour
and the Z back, and compares each with the model run against the same
prefill. The setup is re-sent after the last case so MACCESS's Z width is
not left behind; V9XGDI /auto passed afterwards.

A 32-bit-Z trapezoid plus the setup is 35 register writes; the probe now
waits for FIFO room in blocks of 32, the VxD's limit.

## Results

Sixteen cases, all with colour 40/80/C0 and alpha 5A.

| Case | Settles | Result |
| --- | --- | --- |
| Z16Write | ZORG = Z address - 2 x pixel address; Z pitch = colour pitch in pixels; stored value = integer part; Z folds the left edge's steps like colour | PASS |
| Z16ModeE, NE, LT, LTE, GT, GTE | each compare is new against stored, as named | PASS (all six) |
| Z16TestOnly | atype I compares and never writes | PASS |
| Z16Ramp | compares per pixel against a varying stored value | PASS |
| Z16Bottom | -10 rising: stored 0 until the value reaches 0 | PASS |
| Z16Fraction | 1000.5 + 0.25 a pixel: truncated, not rounded | PASS |
| Z32Write | the Z32 pairs and MACCESS.zwidth; all 32 stored bits distinct | PASS |
| Z32ModeLT | 0x7FFFFFF0+x against 0x80000000: the compare is unsigned | PASS |
| Z32Bottom | as Z16Bottom | PASS |
| Z16Top, Z32Top | see below | PASS after the model change |

**The top of the range clamps.** The first run (`b385-MGA2D-depth-first-
model.TXT`) used 86Box's model, in which a 16-bit value past 65535 sets the
32-bit register's sign bit and is stored as 0, and a 32-bit one past 2^32
sets bit 47 and does the same. The card instead stored `FFFF` and
`FFFFFFFF` for every pixel past the top (16 mismatches each, every other
case exact). The model now accumulates exactly and clamps the stored value
to [0, maximum]; with that, all sixteen pass (`b385-MGA2D-depth.TXT`).
Whether the engine's adder saturates or is wider than the register is not
distinguished: these values only rise past the top.

For Direct3D this is the friendly answer: a depth slightly over 1.0 after
interpolation stores the far value rather than wrapping to near.

## Not settled here

- 16-bit Z at a 16 bpp colour depth: the probe runs depth at 32 bpp only
  (Gouraud at 16 bpp dithers). The layout gives a negative ZORG for 32-bit
  Z at 16 bpp in this region; not needed for the plan's 16 bpp start.
- The bank advice (3-91: ZORG at 200000h or 400000h is fastest): 16-bit
  ran at 400000h, 32-bit at 80000h; both are correct, neither was timed.
- Values that run past the top and come back.
- Matrox's own HAL publishes 16-bit Z only; 32-bit is the chip's, measured
  here, and whether to publish it is phase 4's decision.
