# Voodoo4 on the 0.61.0 tree: probes pass but V9XD32's 32-bit textures, 3DMark 2000 draws correctly, and its grabbed frames do not show the screen

Date: 2026-11-27. Machine: A8U4I5 (Pentium III 1 GHz, 128 MiB, Windows
98 SE), its Voodoo4 4500 PCI (`121A:0009`, subsystem `121A:0005`).
Build: the `3dfx` package of `6244dc08-dirty` (the 0.61.0 tree),
installed by `run-release-checks.ps1 -Machine voodoo4` (WININIT renames,
`reset`, 6 of 6 files hash-checked, boot 720 to 721). The fourth card
of the A8U4I5 round, and the first `3dfx` run of the 1.0 work; the
last Velocity9x runs on this card were October's.

## Getting the card onto our driver

The card came back in PCI slot 8 where October had it in slot 9, so
Windows made a new devnode (`BUS_00&DEV_08&FUNC_00`) with no driver.
The inventory's display line named "NVIDIA GeForce2 GTS", an old class
key, not the card. Setting the new devnode's `Driver` to
`Display\0014` (Velocity9x's VSA-100 key from October) was not enough:
at the next boot Windows ran New Hardware Found with 3dfx's own INF
(`3DFXVS.INF`, matching subsystem `0005`), asked for its disk, and,
with every file cancelled, rewrote `Display\0014` with 3dfx's values
(`3dfx16vs.drv`, `3dfxvs.vxd`). The agent refuses writes under
`HKLM\System`, so the key was restored the way a user would: the
package copied to `C:\V9X3DFX`, Device Manager, Update Driver, Have
Disk, "Velocity9x 3dfx VSA-100", past Windows' "closer match" warning.
Boot 718 came up at 800x600 on Velocity9x; Windows then installed the
monitor from its own `MONITOR.INF`.

## Two runner faults this card found

`run-release-checks.ps1` had never run a family that ships no Glide.

1. It staged `GLIDE2X.DLL` and `GLIDE3X.DLL` from a package without
   them, copied nothing, and failed both on hash against 3dfx's own
   (run 1, "installed: 6 of 8"). It now stages only the files the
   package holds.
2. Its 3DMark freeze watch counted only accepted flips (`FlipHandled`).
   The VSA-100 claims no flip, so every flip is declined to
   DirectDraw's copy (`FlipDeclined=1480`, `FlipHandled=0` at 2.6
   minutes) and run 2 was stopped as frozen while the Adventure test
   drew at 7.4 fps (116,416 primitive calls). It now takes a change in
   Direct3D draw calls as progress too.

The generated record still says "All eight files" and "6 of 8"; its
sentence is fixed text, its count is not.

## Release checks (run 3)

| Check | Result |
|---|---|
| V9XD32 `/bpp16` | FAIL, one test: T22 (32-bit textures draw black) |
| V9XGLP, V9XWPRS, V9XFBCMP | PASS |
| V9XR3DP | COMPLETE |
| V9XGLIDP | FAIL at `FogTable` (white where blue was expected); every other step passes. This is 3dfx's own Glide, which the package keeps |
| 3DMark 2000, default benchmark | ran to its score, 577 (recorded, not compared) |

**T22:** the A8R8G8B8 and X8R8G8B8 textures are created, locked and
drawn without an error, and every judged pixel reads 0; T6, the same
test at 16 bits a texel, is exact
([issue](../issues/2026-11-27-voodoo4-v9xd32-32bit-textures-draw-black.md)).

**3DMark's grabbed frames are not the screen.** The ten frames V9XTRACE
grabbed are badly corrupt: the Helicopter test's trees and cockpit
displays are noise, Adventure's ground and some walls are noise, the
loading screen's text is garbled (`voodoo4/3dmark2000-grabs.jpg`), and
the counters flag 219,965 draws "into the page on screen". Live
screenshots of a second 3DMark run on the same build, taken every 15
seconds through both game tests, show every texture correct
(`voodoo4/3dmark2000-live-screenshots.jpg`). The grab and that counter
work from the flipped page; with no flip accepted there is none, so on
this family both read something other than what is displayed. Run 2's
one live screenshot (windows drawn without the walls around them, in
Adventure) is the only frame that looked wrong on screen, and is not
explained; it was not seen again in the 14 screenshots of the later run.

## Released 0.17.0, the A/B

0.17.0 (13 October, the release after the Voodoo4's Direct3D work),
unpacked and installed by the same runner (`voodoo4-0170`,
`PackageDir`), with today's `V9XTRACE.EXE` put in its folder because
0.17.0's has no `[Card]` section and the runner stopped before
installing. 5 of 5 files hash-checked, boot 721 to 722
([evidence](../probe/voodoo4-1.0-2026-11-27/ab-0.17.0/)).

- V9XD32 `/bpp16`: T22 fails the same way (`T22AOk=0`, `T22XOk=0`),
  so it is not a regression.
- 3DMark 2000 ran to its score, 578 (recorded, not compared); its live
  screenshots are as correct as today's. Today's V9XTRACE could not
  read 0.17.0's counters, and the grab files the runner fetched were
  run 3's left on the guest (byte-identical), so they were deleted from
  the evidence.
- V9XGLIDP fails to open, V9XR3DP fails to negotiate, V9XFBCMP finds
  91 differing pixels in the taskbar clock's box: today's probes
  against an October driver; not read further.

The current build was reinstalled afterwards (boot 722 to 723, 6 of 6).
