Date: 2026-11-25. Machine: W9QI0DAD (AMD FX-6300, Windows 98 SE), ASUS
GeForce 210, GT218 `10DE:0A65`, `nvidia` family, 1024x768x16, remote
agent 0.19.0, boots 150-155. Blocker B13 of
[release-1.0.0.md](../plans/release-1.0.0.md): "an update taken on
physical hardware; one rollback from the backup". Evidence:
[`../probe/gt218-b13-update-w9qi0dad-2026-11-25/`](../probe/gt218-b13-update-w9qi0dad-2026-11-25/).

`enable-ok`.

- **Package:** `releases/0.59.0/velocity9x-0.59.0-nvidia.zip`. Its
  SHA-256 `D79AB34D...` matches `SHA256SUMS.txt`. It was unpacked to
  `C:\V9X059N`.

  - One compatible model, "Velocity9x NVIDIA GeForce 210".
  - Windows warned that the current driver may be a closer match. That

  - No prompt for `V9XDISP.DRV`.
  - SetupX staged the two files in use (`V9XDISP.DRV`, `V9XHAL.DLL`) in

  - `GLIDE2X.DLL` and `GLIDE3X.DLL` kept the newer dev copies, as on the
    netbook the same day
    ([B10 netbook record](2026-11-25-1.0-b10-have-disk-intel-gma-netbook.md)).
    They were put in place by the agent, so the update below started

For B10 this is a signed released zip by Have Disk on the `nvidia`

## 2. Check for updates, 0.59.0 to 0.60.0 (boot 152)

On the Velocity9x tab ("Version: 0.59.0"), Check for updates:

1. **Consent:** "This contacts michaeldale.com.au and sends only the
   installed version (0.59.0) and card family (nvidia)." Answered Yes.
2. **Offer:** "Velocity9x 0.60.0 is available", with the release notes.
   Update now.
3. **Ready:** a few seconds later, "0.60.0 is ready to install... the
   current ones are kept in `C:\V9XDIAG\UPDATE\BACKUP\V0_59_0`".
   - **Staged:** ten files under `C:\V9XNEW`, and `WININIT.INI` with
     ten `dest=src` lines and no `NUL=`.
   - **Backup:** the ten 0.59.0 files (each byte-equal to the 0.59.0
     zip), plus `OEM.INF` and `REGISTRY.REG`.
   - **RunOnce:** `V9xUpdateFinish=...V9XUPD.EXE /FINISH`.
4. **Restart:** Restart Windows now: Yes, Windows' own restart, not the
   agent's. The agent was back in a minute, behind the usual network
   logon box.
5. **`/FINISH`:** "Velocity9x was updated to 0.60.0 (build b3996f07).
   The driver now running reports build b3996f07."

Checked from the host:
- all ten files match the 0.60.0 zip by SHA-256;
- no `WININIT.INI`, and `C:\V9XNEW` is gone;
- `V9XUPD.INI` has `State=committed`, `From=0.59.0`, `To=0.60.0`,
  `RunningBuild=b3996f07`;
- `V9XBOOT.INI` reads `enable-ok`, 1024x768x16;
- Display Properties opens on "Version: 0.60.0", mini-VDD `b3996f07`.

This meets the plan's phase 5 gate on physical hardware: matching
hashes, the new build in `V9XBOOT.INI`, working Display Properties, no
pending `WININIT.INI`.

## 3. Rollback from the backup (boots 153-154)

RECOVER.TXT's "After an update" steps are:
1. Safe Mode Command Prompt Only.
2. `COPY V9X*.* C:\WINDOWS\SYSTEM` from the backup folder.
3. Restart, then double-click `REGISTRY.REG`, and restart again.

The agent cannot drive Safe Mode or DOS, so the same file replacement
was done by `WININIT.INI` renames from a staged copy of the backup. The
backup folder was left whole.
- **Boot 153:** all ten SYSTEM files match 0.59.0 again, `enable-ok`.
- `REGEDIT /S ...\V0_59_0\REGISTRY.REG` exited 0; then a `reset`.
- **Boot 154:** `enable-ok`, 1024x768x16. The Velocity9x tab reads
  "Version: 0.59.0", mini-VDD `6899f1cd`.

**What this rollback did not exercise:**
- RECOVER.TXT's literal path: Safe Mode, `COPY`, a double-clicked `.reg`.
- Any registry or INF change. The 0.59.0 and 0.60.0 `nvidia` INFs are
  byte-identical, so the update changed no registry value and no
  `OEMn.INF` content, and `REGISTRY.REG` had nothing to undo.
- The import surviving a hard reset. A `reset` followed the import with
  no clean shutdown, and since nothing differed, there was nothing to
  check.

**RECOVER.TXT gaps** (the first fixed the same day: step 2 now copies
`*.DRV`, `*.VXD`, `*.DLL` and `*.EXE`, every program file the updater
backs up, since all come from `C:\WINDOWS\SYSTEM`):
- `COPY V9X*.*` names only the `V9X*` files. The updater also replaced
  `GLIDE2X.DLL`, `GLIDE3X.DLL` and `ATI3DCIF.DLL`, so the literal steps
  would leave those three at the new version.
- RECOVER.TXT says nothing about the backed-up `OEM.INF`.

## Seen on the way

The Velocity9x tab shows "Video memory: 14 MB" on this 1 GB card, in
0.59.0 and 0.60.0 alike. `nvidia` has no register decode, so the tab
falls back to `VbeVramBytes`, the VBE BIOS's 4F00h total: 224 x 64 KB
(`VbeController mem=224`). The driver itself works with 128 MiB
(`VddReserve vram=134217728`). B7's HD 5770 "16 MB" may be the same
display; that report was not read here, so B7 stays open.
