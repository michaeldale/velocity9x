# B5 and B9 on 86Box: the DOS box round trip passes on vbe, matrox and ati; after Stand By the s3 and ati screens stay off

Date: 2026-11-24. Machine: 86Box 6.0 build 9001, the B10 clones of
`Win98SE-Native-S3` (ym430tx, Pentium MMX, APM, no ACPI), each on host
port 9879, build `6f5ce760`/`c0b75307` packages (the driver code is the
same in both). Emulator evidence only: none of it says what silicon does.

## B5: full-screen DOS box and back

The round trip of the 2026-11-10 record, scripted
(`dos-roundtrip.ps1`): Start > Run `command`, `echo AAA` windowed,
Alt+Enter, `echo BBB` in full screen (ended by CTRL+M), Alt+Enter back,
`echo CCC`, `exit`. Host-side PrintWindow captures at each step, the
agent pinged at each step, its GDI screenshot after the return and after
`exit`.

| Guest | Package | Result |
|---|---|---|
| Millennium, fresh clone (`Win98SE-B10-VBE3`) | `vbe` (generic, VBE LFB) | pass: full screen shows AAA and BBB; back on the desktop, repainted, AAA, BBB, CCC in order; `exit` returns to a clean desktop; agent answered at every step |
| Millennium (`Win98SE-B10-Millennium2`) | `matrox` | pass, the same |
| Mach64 VT2 (`Win98SE-B10-Mach64`) | `ati` | pass, the same (the navy background is Windows' Active Desktop wallpaper, on before the trip) |

B5 asks for one physical S3 card, one `ati` Radeon and `vbe`. This
covers `vbe` on an emulated card; the Mach64 VT2 is an `ati` row but not
a Radeon. The ViRGE/DX passed the same trip on 2026-11-10.

## B10: vbe on a card with a linear frame buffer

The ViRGE/DX `vbe` install of the B10 record stopped at
`fail-hardware-vbe-mode`. On a fresh Millennium clone the same `vbe`
package, by Have Disk over Windows' Matrox driver (one model, the
"closer match" warning answered Yes, Tag `0x3EEABBC9` straight after the
copy): `Stage=enable-ok`, `VbeController=v=0200 mem=64`, 1024x768x16,
`ModeSwitching=vbe-lfb`, `Adapter=Generic VESA adapter (no chip-specific
support)`, the tabs at top level
(`../probe/1.0-b10-have-disk-ati-matrox-vbe-2026-11-24/vbe-millennium/`).

## B9: Stand By and resume

Start > Shut Down offers Stand By on this board. 86Box implements it by
pausing the emulator (its toolbar button turns to Resume); Resume is the
wake. The card is never powered down, so this cannot show whether a real
resume loses the mode; it does show what the driver leaves on screen.

| Guest | Driver | Screen after resume | V9XWPRS after resume |
|---|---|---|---|
| Millennium | `vbe` | desktop | PASS (DirectDraw and GDI read back, 1024x768x16) |
| Millennium | `matrox` | off ("Monitor in sleep mode") at first, desktop some seconds later | PASS |
| Mach64 VT2 | `ati` | **off**, after pointer moves, a V9XWPRS run, two minutes, and a V9XMSW mode set to 800x600 and back (both exit 0) | PASS |
| Mach64 VT2 (`Win98SE-VBE-Tier0`) | ATI's own "ATI Graphics Pro Turbo PCI (atim64 - VT)" | desktop | not run |
| ViRGE/DX (`Win98SE-B10-S3d`) | `s3` | **off** after 20 s and pointer moves | PASS |
| ViRGE/DX (fresh clone `Win98SE-B10-S3ctl`) | S3's own | desktop | not run |

GDI and DirectDraw keep drawing into the frame buffer while the screen is
off (the agent's GDI screenshot shows the desktop on the Mach64); what is
lost is the scanout.

What reaches the mini-VDD, from a `-VesaTrace` build of `s3` on the
ViRGE clone (the trace now prints the function and BX; COM1 captured from
the 86Box pipe, `b9-s3/com1-vesatrace.txt`): across Stand By and resume,
four 4F15h DDC reads and one 4F02h mode set (BX 8116h), each passed on to
the BIOS. No 4F10h. No `SET_MONITOR_POWER_STATE` call either: the
callbacks are installed (`power-callbacks-ok callbacks=4`), but
`GetMonitorPowerStateCaps` reports D0 only, by the 2026-08-11 decision
([2026-08-11-monitor-power-management.md](2026-08-11-monitor-power-management.md)),
which withheld the low-power states because the display was lost after a
monitor-off timeout. So the screen goes off by a route that does not pass
through our hooks (the APM BIOS is the first suspect, not shown), and on
`s3` and `ati` nothing of ours turns it back on, where the vendors'
drivers do. Not found: which register 86Box reads as "sleep" for each
card, and what the vendors' drivers write on wake.

Filed as [an issue](../issues/2026-11-24-s3-ati-screen-off-after-standby-86box.md).
B9's acceptance (one laptop) is not met by this.

Evidence: [`../probe/1.0-b5-b9-86box-2026-11-24/`](../probe/1.0-b5-b9-86box-2026-11-24/),
with the round-trip, capture and host-mouse scripts. The S3d clone was
left on the trace mini-VDD.
