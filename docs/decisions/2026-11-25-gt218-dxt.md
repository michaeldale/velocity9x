# GeForce 210 DXT: sampled from tiled copies in the texture pool; T19's Dxt1 and Dxt3 pass first boot, 3DMark 2001 SE runs on DXTC

Date: 2026-11-25. Machine: W9QI0DAD (AMD FX-6300, Windows 98 SE), ASUS
GeForce 210, GT218 `10DE:0A65`, desktop 1024x768x16, boot 150. Build
`ad55382a-dirty` (this change). Step 7 of
[nvidia-gt218-ps11.md](../plans/nvidia-gt218-ps11.md).

## What was built

- **Where the sampler reads DXT.** Every DXT texture, one level or a
  chain, gets a record and a tiled copy in the 32 MiB texture pool the
  mipmaps use, and the TIC points there. Mesa's nv50 lays compressed
  textures out only block-linear, so that layout was taken as given.
  **Not measured:** whether Tesla could sample a DXT level pitch-linear.
  The step's "probe first" was skipped because the tiled route does not
  depend on the answer.
- **Layout.** `v9x_nv50_d3d_dxt_layout` is nv50_miptree.c's tiled layout
  counted in 4 x 4 blocks: each level's texels halved and then rounded up
  to blocks, the tile mode chosen on rows of blocks.
- **Copy.** The 2D engine copies each level's rows of blocks as A8R8G8B8
  pixels of the same bytes, since tiling is a matter of bytes and rows.
- **TIC.** Mesa's DXT1_RGBA, DXT3_RGBA and DXT5_RGBA rows (sizes 24h, 25h
  and 26h, UNORM, R G B A). DXT2 and DXT4 are not published.
- **Lock.** The linear levels sit at a 64-byte row pitch for the copy.
  The runtime writes a DXT level's rows packed whatever lPitch says (the
  HD 4600's boot 156), so a level whose rows are narrower is pointed, for
  the length of the lock, at a packed copy in the locking process, as on
  the HD 4600 and GCN.
- **Refused.**
  - A DXT texture with no pool record is not drawn (counted as a
    texture-shape refusal).
  - A DXT cube is not placed. DirectDraw places it and its draws are
    refused. Cubes are claimed for every format, so a program can create
    one. **Not handled:** UT2004's DXT5 cubes, which the HD 4600 needed.

Host tests: the layout (64x64 DXT1 chain, 16x8 DXT5, 12x12 rounding,
refusals), the three TIC rows, and the map's DXT paths (no copy refused,
one level tiled at level 0, chain with a mip filter). Gates:
`build-host.ps1` and `run-checks.ps1` passed.

## On the card

Release checks: 6 of 6 probe runs exited 0, and V9XD32 reported `Result=PASS`
([release/](../probe/gt218-dxt-w9qi0dad-2026-11-25/release/)).

| T19 row | Before (boot 149) | This build |
|---|---|---|
| Dxt1 | skip-no-dxt (CheckDeviceFormat 8876086A) | pass: 0 mismatches, worst channel 8 of tolerance 9 |
| Dxt3 | skip-no-dxt | pass: 0 mismatches, worst channel 9 of 9 |

T19's Dxt1 texture has a 16-byte row pitch (`T19Dxt1Pitch=10h`), below
the 64-byte pitch of the copy, so the packed-lock path was used. Every
other V9XD32 key matched the boot-149 run, the build id and timings
aside.

**3DMark 2001 SE**, default run with `VSync=1` set for the run and
`VSync=2` put back afterwards (hash checked):
- **Score:** 2362 before this change, 2510 now. Recorded, not compared.
  The settings line now reads `DXTC` where it read `T32`, so every game
  test loaded compressed textures.
- **Counters:**
  - no engine timeouts, faults or new resets;
  - no texture refused, and the texture-shape refusals (`M64Policy10`)
    stayed at 0, so no DXT texture went without its copy;
  - `M64Policy19` 0 to 160, the same guard-band drops as every earlier
    run;
  - 1,068 textures placed (6.7 MB of linear levels);
  - `FlipVSyncOverridden` unchanged.
- **On screen:** 22 of 94 OBS frames inspected
  ([obs/](../probe/gt218-dxt-w9qi0dad-2026-11-25/obs/)), covering Car
  Chase, Dragothic, Lobby and Nature at both details. Every scene was
  textured as in the uncompressed run, and Nature drew its snow-capped
  mountains, the distant tree line, the rock face close up, trees and
  grass.
  - One Car Chase frame (`gt218-dxt-19.png`) has a pale, flat patch of
    ground behind the truck. The uncompressed run has no frame at that
    moment to compare, so it is unexplained, not known bad.
  - The feature tests' frames were not inspected.

## Not shown

- Whether the sampler reads DXT pitch-linear.
- How full the pool gets. A DXT-heavy program that fills it loses its
  later textures; none was refused here.
- DXT cubes.
- Nature's Image Quality frame (step 8 of the plan).
