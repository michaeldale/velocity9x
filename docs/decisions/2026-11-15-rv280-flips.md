# RV280 flips on the legacy CRTC

Date: 2026-11-15

Machine: M-HNBJNV, Radeon 9250 (`1002:5960`), Windows 98 SE. Build:
branch `ati-rv280`, `539fb5ce-dirty`. All eight driver files were
installed by WININIT renames with each staged copy hash-checked; boot
19. Phase 4 of
[`../plans/ati-rv280-radeon-9250.md`](../plans/ati-rv280-radeon-9250.md).
Evidence: [`../probe/rv280-flips-2026-11-15/`](../probe/rv280-flips-2026-11-15/).

## Before

On the 2D-only row (boot 18), V9XDDP read `FlipHr=0` with `Flip20Ms=0`.
The flip reached no register the CRTC scans from
([record](2026-11-15-rv280-2d-write-probe.md)).

## Change

`src/display32/engines/rv280_scanout.c` implements the flip, following
Linux `r100_page_flip` and `r100_page_flip_pending` (`r100.c:164-213`):
- write `CRTC_OFFSET` with `OFFSET_LOCK` (bit 31) set;
- wait for `GUI_TRIG_OFFSET` (bit 30) to rise;
- write the same address unlocked, which the CRTC takes at the next
  vertical blank.

The flip is pending until bit 30 clears. Three helpers support it:
- **The address:** `eng_rv280.c`'s `v9x_rv280_flip_address`. It is the
  frame buffer's GPU base plus the surface's offset, taken after the 2D
  engine is idle, and checked by `v9x_rv280_crtc_start`, which is
  host-tested in `tests/host/test_rv280_crtc.c`.
- **The live test:** flips are taken only while `CRTC_OFFSET_CNTL` is
  untiled, mono, not locked, latched at the blank, and has
  `CRTC_GUI_TRIG_OFFSET_LEFT_EN` (bit 28) set. The register probe read
  `10000000h` under VBE at every depth: exactly that bit.
- **Dispatch:** the shared scanout code (`i9xx_scanout.c`) sends the
  RV280 here, and `rv280_hw16.c` stamps `V9X_DD_ENGINE_CAP_FLIP`.

The registers are the Rage 128's offsets (`r128_scanout.c`), but that
chip writes `CRTC_OFFSET` without the lock.

## Measured

- **`V9XHW.INI`:** `EngineCaps=00000007`, which is fill, copy and flip.
- **V9XDDP flips:**

  | Mode | `Flip20Ms` | `FlipMaxMs` |
  |---|---|---|
  | 1024x768x16 | 331 | 20 |
  | 1024x768x32 | 328 | 18 |
  | 640x480x8 | 331 | 19 |

  20 flips at about 16.5 ms each: each waited for a 60 Hz blank.
  `FlipHr=0` in every mode.
- **Other V9XDDP checks:** fill, source copy, colour-keyed fill and the
  four overlap copies are all still `PixelOk=1` at every depth.
  `FlipPixelOk=0` is expected and is not a verdict: it reads the screen
  back through GDI, which sees a fixed page once flips are real
  (`docs/issues/2026-09-02-flippixelok-is-uninterpretable.md`).
- **V9XTRACE** (16 bpp run):
  - `FlipHandled=23` and `FlipTakenAtDone=23`: the CRTC had cleared the
    pending bit for every flip the state machine called done;
  - `FlipNotTakenAtDone=0`, `FlipDeclined=0`, `EngineIdleTimeouts=0`;
  - `FlipStillDrawing=117945` is DirectDraw polling GetFlipStatus while
    a flip waits for its blank.
  - `BuildsAgree=0` only because the V9XTRACE copy on the machine is
    the previous build (`19ec1531-dirty`). The driver and HAL report
    the same build.
