## What changed since 0.43.0

Every probe verdict compared with `0.43.0-release-checks-2026-11-08`, by machine and check.

- **i5-4570, HD 4600**: no verdict changed. This was its second attempt. In the first, with the other five machines, a staged file arrived only in part (`V9XNVXD.BIN` left as a `.PART` file, agent 0.13.1), the `reset` reported no boot, and the machine was off the network for about 20 minutes. It came back at boot 196 on the old driver, with nothing installed. The rerun (`-Machine hd4600 -SkipProbeBuild`, same probes) installed and passed. The record was then rewritten with `-SummaryOnly`.
- **Netbook, GMA 950**: no verdict changed.
- **A8U4I5, Rage 128 Pro**: no verdict changed.
- **M-6B21TJ, GM45 GMA 4500MHD, HP t5740 (remote help)**: not in the 0.43.0 checks; nothing to compare. Same verdicts as the run on `e9d361b5-dirty` earlier the same day (`docs/probe/w9qi3dab-gl40-audit-2026-11-08/release-check-gm45/`). V9XGLP's PASS hides two-unit REPLACE and DECAL failures, the same as on Ironlake and the GMA X3100 before this release ([issue](../issues/2026-11-08-gen4-keyed-depth-write-draws-dropped-forsaken.md)).
- **M-7V636C, RIVA 128ZX (remote help)**: not in the 0.43.0 checks. Against its last checks (`0.39.0-release-checks-2026-11-07`), nothing changed: GLIDP `BlendHalf` still reads `7BCF` (expected `8410`), and V9XD32 `/bpp16` still has `Failures=0x00000001`. This release did not change any NV3 code; its one source change is Gen4's `d3d_g4.c`.
- **M-JJN1ZZ, Radeon R3E Mullins (remote help)**: no verdict changed.
