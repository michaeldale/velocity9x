Date: 2026-10-27

Status: measured on three machines, all on `780ddde9` (main with the
HD 5450's flips and 128 MiB heap) from a clean tree (`build=780ddde9` in
V9XHAL.DLL). The HD 4600 and GMA 950 ran `100e041c`; see
[`2026-10-27-0.32.0-release-checks-intel.md`](2026-10-27-0.32.0-release-checks-intel.md).

## Open: the Rage 128 hung in 3DMark 2000 once

Run 1 hung A8U4I5 and it needed a power cycle. V9XTRACE, flushed at the
fault, holds `FaultCode=0x52314343` (`R1CC`, `r128_cce.c`'s idle wait)
with `FaultAddress=0x80030000` (the CCE status when the wait gave up) and
one engine idle timeout; the last ring entry is a `D3dDrawPrimitives`
enter. That path resets the engine after the flush, and the machine
still did not recover. Run 2,
after the power cycle, completed. No Rage 128 file changed since 0.30.0;
the suspect is main's shared-core change to the attachment-list (mip)
walk, unmeasured. One hang in two runs is not enough to bisect on, and
it was not reproduced.

## Parked: one wrong Game 1 frame on the Ironlake

Parked on Michael's decision (2026-10-27): it is not a regression. The
same symptom was recorded on 22 October, before 0.28.0, and the score
(2913) matches the 25 October write-combining record (2909).

The first capture of Game 1 (`3dmark-game1-slab.png`, before the
mission-time panel is up) shows a dark piece of hillside with straight
polygon edges in front of the helicopter and a tank; the rotor blade
shows through it, the nearer light hill on the right hides it. It is the
same symptom as the unexplained frame in
[`2026-10-22-ironlake-direct3d.md`](2026-10-22-ironlake-direct3d.md),
also early in Game 1. A second run captured at mission time 15.0 and
23.1 draws correctly (`3dmark-game1-t15.png`, `3dmark-game1-t23.png`).

The snapshot after run 1 (`V9XSNA6-3dmark.INI`) has every draw on the
Gen5 engine: no refusals, no engine timeouts or resets, 2,677,819
asynchronous submits. Ruled out by reading `d3d_g4.c`, not measured:
state carried from one batch to the next (each batch's state is built
from the draw and written to a slot the GPU has finished with), and a
depth clear out of order with queued draws (the fill is two triangles
through the same slots). Not yet tested: the core's clip to the target
for triangles the runtime sends inside the 8191-pixel guard band.

## Notes

- A8U4I5's first V9XGLIDP run reported 2 failures. It had started while
  V9XGLP's report still said `Result=RUNNING`, so the two overlapped; run
  alone it passed (`glidp-alone-V9XGLIDP.INI`). The probe script now
  waits past `RUNNING` and `PENDING`.
- A8U4I5's V9XD32 reports carry `-t14nomode` in their names. V9XD32
  only matches `/t14nomode`, so the dash form did nothing and T14 ran
  its default child, as on the other machines.
