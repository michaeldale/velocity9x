# 0.24.0 regression runs: Millennium II and GMA 950 on merged main

Date: 2026-10-22
Status: **measured, two machines, one build** (`main` at `cd04a7b8`, the
packages run-checks built). Captures:
`docs\probe\0.24.0-regression-a8u4i5-netbook-2026-10-22\`.

Render ABI 6, OpenGL at 32 bpp and the 24/32-bit depth format were
measured only on the HD 4600 when they merged (9d4c7012). These are the
runs that commit said it owed: Gen3 and the MGA's 32-bit Z.

## Install

Both machines took their family's runtime set by WININIT rename, renames
only, no `NUL=`:

| Machine | Files | Restart | Boot |
|---|---|---|---|
| A8U4I5, Millennium II MGA-2164W, 800x600x16 | DRV, VXD, HAL, SETP, GL, TRACE, GLIDE2X, GLIDE3X (SYSTEM's ATI3DCIF is ATI's own) | `reboot` | 515 |
| Netbook (W9QI2BE2, GMA 950), 1024x576x16 | the same plus ATI3DCIF | `reset` | 214 |

Every file's size on the guest matched the build afterwards. The
netbook's agent went from 0.10.0 to 0.12.0 by `update` first; its
DOS-VM step was refused by the agent's own `allow_dos_vm=0`, and the swap
applied without it. The netbook now answers at 10.0.1.254.

Each 32 bpp run's INI records `DesktopBitsPerPixel=32`. The Millennium
II's desktop went to 800x600x32 by V9XMSW and back to x16; the netbook's
to 1024x576x32 and back.

The Millennium II's Glide 2 failure is the one boot 501 recorded:
`BlendHalf=FAIL read=FFFF expected=8410+-1 at=570,320`. Blends there are
drawn as Direct3D's stipples (`mga2164w-gl-glide-parked`), so one sampled
pixel reads a full colour. Nothing new.

## The ABI 6 break, met for real

V9XGLIDP first failed to open on the Millennium II: `Result=FAIL open`,
and the HAL snapshot named no Glide process at all. `C:\V9XGLID` held its
own GLIDE2X.DLL from an earlier session. Windows loads the copy beside
the program first, and a pre-ABI-6 Glide gets no render interface. With
the folder's copy replaced by the build's, it opened and ran as above.

Diablo II's folder had the same kind of copy, a pre-ABI-6 glide3x.dll
(84,992 bytes). It is kept beside the new one as `glide3x.v23`. With the
new one, `Diablo II.exe -3dfx` drew the title, the main menu, the
character screen, the loading screen and the Rogue camp (Glide 3, 640x480
in game). WCLOSE ended it, and the desktop came back at 800x600x16.

This is the break the 0.24.0 changelog states. These two folders are why
the release notes have to say it in their first lines: an install that
leaves old copies beside games turns Glide off for those games, silently.

## ChoosePixelFormat picks the deep format on the Millennium II

V9XGLP with no /format asks ChoosePixelFormat for 32 depth bits, as
GLQuake does. On the Millennium II that returned format 2
(`ChosenFormat=2`, `ChosenDepthBits=32`), whose depth is exactly 32 bits
there. On the HD 4600, where format 2's depth is 24, the same request got
format 1 with 16 (9d4c7012). So the 0.24.0 changelog's "ChoosePixelFormat
still hands GLQuake-style requests the 16-bit format" holds only where
the deep format is not exactly 32. It is corrected.
