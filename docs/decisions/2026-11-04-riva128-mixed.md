# RIVA 128ZX: the Mixed checks pass; they only run under /mixed

Date: 2026-11-04

Machine: M-7V636C (remote help), RIVA 128ZX 8 MiB, Windows 98 first
edition, boot 32 (b5d1e2ba), desktop 800x600x16 at 5:5:5. File:
`docs/probe/m7v636c-riva128-games-2026-11-04/b32m-V9XDDT.TXT`.

## What the list said

MixedOk, MixedOrderingOk, MixedColorEncodingOk and MixedDepthEncodingOk
were on the open list as "mixed 2D/3D" failures since boot 26. They run
only under V9XDDP `/mixed`, a HAL draw, then CPU writes to the colour
and depth surfaces, then HAL draws again; a default run leaves MixedRun 0
and the keys at their "not run" values. Like the D3DZP keys
([record](2026-11-04-riva128-zprivate.md)), never a failure.

## V9XDDP /mixed, boot 32

- First HAL draw: colour 7C00h (red), depth 8000h.
- CPU stores: colour 03E0h (green), depth 4000h, read back as stored.
- A HAL draw behind the CPU's depth: rejected, 03E0h and 4000h kept.
- One in front: 001Fh (blue), depth 6000h.
- MixedOrderingOk, MixedColorEncodingOk, MixedDepthEncodingOk and MixedOk
  all 1: the engine and the CPU see each other's writes in order, and
  both encode colour and depth the same way (depth is z x 65536, as the
  state probe measured).
- 217 of 227 `Ok` keys in that run: everything the default run passes
  plus the four.

No change to the driver. What is left on the default list is 8 keys:
32-bit textures (2), decal alpha (2), the bilinear half texel, the two
trilinear blend checks and FlipPixelOk.
