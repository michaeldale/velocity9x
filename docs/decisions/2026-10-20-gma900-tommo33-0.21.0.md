# GMA 900 on 0.21.0: probes pass, 3DMark 2001 SE runs at 16 bpp, 1,137 draws refused

Date: 2026-10-20. Machine: TOMMO33, a tester's Acer (Garda-910 board,
915GM, GMA 900 8086:2592 rev 3, Pentium M 1.5 GHz, 640x480x16 desktop),
reached through remote help as relay `M-NGMX0T`. Build `19e68824-dirty`
(0.21.0; driver, HAL and trace agree), replacing the tester's 0.19.0. DirectX 9.0c.
Evidence: [`../probe/tommo33-gma900-0.21.0-2026-10-20/`](../probe/tommo33-gma900-0.21.0-2026-10-20/).

This was the first run of 0.21.0 on a Gen3 chip. The shared changes
reach Gen3: the D3D8 `TEXCOORDINDEX` fix (`19e68824`) and the
`v9x_present_gdi_may_draw` rule in `ddhal_core.c`. The Haswell pipelining does not.

## Probes

- V9XDDP: COMPLETE, 207 checks `Ok=1`, 17 `Ok=0`. Three more `Chain*`
  checks pass than in the netbook's 0.19.0 run (`ddp/`).
- V9XD32: passes at 16 and 32 bpp, each with Z16 and Z24 (`d32/`).

## 3DMark 2001 SE (build 330, Pro)

The default 1024x768x32 with Z24 failed to start:
`setFullscreen - creating the device failed : D3DERR_OUTOFVIDEOMEMORY`.
That refusal is correct. The DirectDraw heap here is 6.1 MB
(`GblHalVidMemTotal=0x0061A000`; 3DMark reports 8 MB), and a front
buffer, back buffer and 24-bit Z at that size need 9 MB. The 16 MiB
GMADR cap and the heap to-do in `STATUS.md` cover this. The 945 shares
the table entry, so the netbook probably has the same limit; that was
not checked.

Run at 1024x768x16, Z16, 16-bit textures, double buffered, D3D software
T&L: **280 3DMarks** (non-default settings). Recorded, not compared.

Five frames of the run were filmed at 30-60 s intervals. The one that
caught a game test is Dragothic (`3dmark2001se/dragothic.png`). It
draws correctly: the dragon, the tower and the rock are textured, with
no mosaic.

The Pro Image Quality test saved one frame from each of three game
scenes (`3dmark2001se/IQ01I.png` to `IQ03I.png`: Car Chase, Dragothic's
village, Lobby). The Lobby frame (`IQ03I`) is textured correctly, with
no mosaic, so the `TEXCOORDINDEX` fix holds on Gen3.

## The engine

One snapshot was taken after the run (`3dmark2001se/V9XSNA2.INI`). It
covers the whole boot: V9XDDP, V9XD32 and 3DMark.
- 756,201 draws submitted. 759,988 async submits, 1,655 synchronous.
- 0 FIFO, idle, breadcrumb or ring-space timeouts. 0 resets.
- **1,137 draws refused, last reason 6 (`V9X_I9XX_REFUSE_VERTICES`)**.
  A vertex-run builder (`d3d_i9xx.c`) refused the stream. The tester's
  previous snapshot (`V9XSNA1.INI`, Deus Ex on `f0f12a6b`) has 0
  refusals. Attributed by test below.
- 16,738 mip trees declined for room (last reason 4), the 6.1 MB heap
  again. Textures that did not fit fell back to what 3DMark does
  without them.
- One texture refused for system memory, 492 driver-info queries
  declined. Neither was investigated.

## Which tests refuse (reason 6)

3DMark was then run again, one selection at a time in the same boot,
with a snapshot after each (`3dmark2001se/per-test/`). The counters add
up from startup, so each row is the difference from the previous
snapshot.

| Selection | Draws submitted | Refused |
|---|---|---|
| Car Chase, low and high | 230,419 | 702 |
| Dragothic, low and high | 224,883 | 0 |
| Lobby, low and high | 214,558 | 408 |
| Fill rate, high polygon, vertex shader, point sprites | 236,006 | 0 |

If the counts repeat from run to run, Car Chase and Lobby account for
1,110 of the first run's 1,137. The other 27 came from outside these
four selections: the Image Quality frames, V9XDDP or V9XD32. That was
not checked.

What the refusal costs. A merged batch refused for reason 6 is
replayed one record at a time (`v9x_d3d_records_batch`,
`r3d_records.c`). Valid records draw, and only a record with a bad
vertex is lost, and counted again. The counters cannot separate first
refusals from replays, so how many triangles are actually lost is not
known. Neither the filmed frames nor the IQ frames show a visible hole.

Why, not yet measured. The builders refuse a whole stream for any
vertex with x outside [0, width], y outside [0, height], z outside
[0, 1], a negative sign bit (−0.0 included), w that is not positive
and finite, or a UV that is not finite (`i9xx_vertex.c`,
`i9xx_multitex.c`, `v9x_i9xx_float_in_range`). The core clips x and y
to the target for Gen3 (`clip_in_core`). Nothing clips z, and nothing
clears a −0.0. The two outdoor scenes with far geometry refuse, and
Dragothic, which has a sky too, does not. That narrows nothing. No
counter names the failing field. Naming it needs a recorder for the
first refused vertex: the field, its bits and the reason.
