# 0.35.0 release checks: the HD 4600, the GMA 950, the HD 7660D, the HD 7470 and the RIVA 128ZX

Date: 2026-11-04

Status: measured on five machines, all on `8ce950a7` from a clean tree
(`8ce950a7` in V9XHAL.DLL of all three packages, and in every probe
report). `run-checks.ps1` passed and the four probes were rebuilt first.
Not covered: the GM45 (no machine; claimed blind for issue 22), the HD
5450 and HD 5770 (no longer installed in their testers' machines), and the
Carrizo (offline).

Evidence: [`../probe/0.35.0-release-checks-2026-11-04/`](../probe/0.35.0-release-checks-2026-11-04/),
one folder per machine. The raw frame grabs are kept out of the tree; each
3DMark run with grabs has a contact sheet (`grabs-sheet.jpg`).

## The RIVA 128ZX: 3DMark 2000 runs, almost all of it on the CPU

3DMark 2000 completed at default settings, its first run on this card. Of
its draws the chip took 2,185 and refused 513,441, which the software
engine drew:
- 391,489 for reason 3, `REFUSE_TEXTURE`: the draw's texture was not
  placed in video memory;
- 121,952 for reason 10, `REFUSE_SURFACE`: a render target the HAL does
  not draw to.

Not looked into: which textures and surfaces, and whether the 8 MiB card
is full. The grabs caught only black frames and the loading screen, since
grabs every 40 flips were spent before Game 1. The 1,437 draws into the
presented page were counted before 3DMark started (V9XDDP and V9XD32 at
boot 37) and did not move during it; not looked into either. The
bring-up's titles (Half-Life, Unreal Tournament, Thief) draw on the chip.

Michael, 2026-11-04: the RIVA 128 work is not finished and this does not
block 0.35.0; the release notes say so.

## The GMA 950's runs

Recorded once, as they happened:

- Boot 270: Half-Life Direct3D sat at "Loading..." with "Playing demo
  from ...mwd5.dem" in its log for six minutes and was killed. 3DMark 2000
  after it crashed inside `3DMark2000.exe` (`C0000005` at `004E23D1`),
  the known issue that the next program crashes after one is killed
  holding surfaces.
- The netbook's agent was then updated to 0.14.0 (`dev-0140`, from
  0.13.0, at Michael's request). That restarts the agent, not Windows: the
  boot-270 session carried on, and a second 3DMark run there also ended
  without a score.
- Boot 272 (after `reset`): Half-Life Direct3D ran mwd5 at 43.8 fps and
  closed normally. The boot-270 stall did not recur; its cause is not
  known. The 3DMark run in that boot was stopped by the check script
  itself, which read the untitled fullscreen windows as 3DMark having
  exited.
- Boot 273 (after `reset`): 3DMark 2000 alone, 1181, with clean counters.

The 0.34.0 record put the missing Half-Life Direct3D result on the
netbook down to the agent's missing `shell` verb. That was not it:
Half-Life rewrites `qconsole.log` each start, so the result would have
been read regardless; the run itself had not finished.
