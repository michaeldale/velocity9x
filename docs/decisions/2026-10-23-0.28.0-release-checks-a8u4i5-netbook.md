# 0.28.0 release checks: Rage 128 games, and the GMA 950 against 0.24.0's set

Date: 2026-10-23

Status: **measured on two machines; the Mach64 flip path not run.**
Evidence:
[`../probe/0.28.0-release-checks-a8u4i5-netbook-2026-10-23/`](../probe/0.28.0-release-checks-a8u4i5-netbook-2026-10-23/).

These are the checks Michael asked for before the GMA 4500 merge.
Builds: A8U4I5 at boot 535 (`90fee727` code); the netbook at boot 234,
from the same tree's intel-gma package, deployed by WININIT rename and
restarted with `reset`.

## A8U4I5, Rage 128 Pro: two games on the final build

The last Direct3D game run (boot 527) was before these changes: the mip
order, flips, the CCE left running, and the drains on validate and flip.

| Check | Result |
|---|---|
| Half-Life Direct3D mwd5 | 32.3 fps cold, 34.4 and 34.3 warm (boot 527: 23.1 and 31.2) |
| its snapshot | 683,925 batches, no refusal, no idle timeout, `EngineFlags=1`-valid |
| Diablo II, Glide 3, the folder's `glide3x.dll` replaced by the package's | title, main menu, character screen and town draw; `WCLOSE II.EXE` returns to the 800x600x16 desktop; machine stays up; 1 draw refused to the CPU |

Half-Life's Direct3D renderer presents by blit here: 3 flips in the whole
run.

## Netbook, GMA 950: the 0.24.0 regression set, at a 16 bpp desktop

This release changed code every chip runs:

- the scanout dispatcher (`i9xx_scanout.c`), which now has Rage 128
  branches;
- the HAL's file list;
- the package file list, which now includes `NOTICES.TXT`.

The set is [0.24.0's](2026-10-22-0.24.0-regression-a8u4i5-netbook.md),
plus V9XDDP for the flip path.

| Probe | Boot 234 | Boot 214 (0.24.0) |
|---|---|---|
| V9XD32, 32 bpp Z16 / `/z24` / `/bpp16` | PASS / PASS / PASS, T8 `0F` each | the same |
| V9XGLP `/format:1` | PASS, 16 depth bits | the same |
| V9XGLP `/format:2` | PASS, 24 depth bits | the same |
| V9XR3DP | COMPLETE; `DrawOk`, `TexturedScissorOk`, `MaskedOk` 1 | COMPLETE |
| V9XGLIDP (Glide 2) | PASS, 0 failures | PASS |
| V9XGL3P (Glide 3) | SESSION | SESSION |

V9XDDP: `Result=COMPLETE`, `FlipHr=0`, 20 flips in 4 ms, the longest
2 ms. That is the same as 0.19.0's run on this machine
(`netbook-gma950-0.19.0-2026-10-18`).

Every `...Ok` flag equals 0.19.0's but two, both checks added after it:

- `Tex8A8888HalvesOk` and `Tex8X8888HalvesOk` read 0. `6b9b4b71` added
  them for Haswell. No Gen3 part offers an 8888 texture, and the Pineview
  and GMA 900 records list the same two.
- `FlipPixelOk=0` is the GDI-readback artefact recorded since August, and
  equal to 0.19.0's.

The 32 bpp desktop runs of 0.24.0's set were not repeated.

## Not run

**The Mach64 family's flip path** (Rage XL, Rage IIC, Rage Mobility). The
Gateway laptop (10.0.1.22) did not answer, and A8U4I5 holds the Rage 128.

By reading the code: every new branch in the dispatcher is gated on
`v9x_r128_scanout_active()`, which is false for any engine type but
`ATI_RAGE128`. The Mach64 tests also come before it in `in_vblank` and
`set_display_start`. This is a reading of the code, not a measurement.
