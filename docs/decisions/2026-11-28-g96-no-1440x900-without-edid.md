# GeForce 9500 GT (G96): 1440x900 is missing because the BIOS saw no monitor

Date: 2026-11-28

Disputed the same day: boots 18 and 20 list 1440x900 with `Edid=none`
too ([2026-11-28-g96-1440x900-listed-again.md](2026-11-28-g96-1440x900-listed-again.md)).

On M-Z2T02D (GitHub issue 30), the owner's 1440x900 was not offered on
the `nvidia` package. `V9XMSW /set:1440x900x32` returned
`ChangeResult=-2`, and the desktop stayed at 1024x768x32.

## What the BIOS lists

The driver sets only modes the video BIOS lists (VBE 4F02h). Two lists
from the same card:

| | Issue 30's `vbe` log (owner, 2026-11-2x) | Boot 13 (`nvidia`, 2026-11-28) |
|---|---|---|
| Modes listed | 29 (`VbeCache l=29`) | 30 (`l=30`) |
| Wide | 1280x800 (8, 32), 1280x720 (32), 1440x900 (8, 32) | none |
| Large 4:3 | none | 1280x1024 and 1600x1200 at 8, 16, 32 |
| Monitor EDID through the card | not logged by that build | `Edid=none` (`V9XMODES.INI`) |

The VBIOS's mode table changed between the two boots, with the same
card and VBIOS (`rev=6294`, 224 x 64 KiB): the wide modes that match a
1440x900 panel were there when it ran `vbe`, and generic 4:3 modes are
there now, with no EDID read through the card. That fits a VBIOS that
builds its list from the display it finds at power-on; it found none
this time. The HD 2500's earlier logs on the same machine read a 1440x900
EDID (`Edid=v=0103 preferred=1440x900`), so the monitor may now be
cabled to the motherboard's output, or reach the 9500 GT without DDC.
Neither is measured; the agent cannot see which connector is used.

## Decision

No driver change: the driver has no mode-set path of its own on this
chip (VBE only, as on the GeForce 210), so it cannot offer a mode the
BIOS does not list. Ask the owner which output the monitor is on, and to
power the machine up with it on the 9500 GT's DVI or VGA; then read
`V9XMODES.INI` again.
