# SiS 6326 Direct3D engine: an untextured batch stalls the next textured one

Date: 2026-10-05. Machine: A8U4I5, SiS 6326 card 2 (rev 0Bh), boots 212 to
228. Evidence: `docs/probe/a8u4i5-sis6326-d3d-engine-2026-10-05/`.
Plan: [sis-6326-hardware-3d.md](../plans/sis-6326-hardware-3d.md), phase 4.
Issue: [2026-10-05 hard locks under V9XDDP](../issues/2026-10-05-a8u4i5-hard-lock-under-sis-d3d-v9xddp.md).
Follows [textures](2026-10-05-sis6326-3d-textures.md).

## What was built

- `d3d_sis6326.c` serves the neutral draw entry.
- `d3d_sis6326_map.c` (host-tested) translates the draw into the
  sis6326_3d.c builders' words.
- Emission is synchronous: the 3D engine is idle before each triangle and
  after each batch.
- The 16-bit side sets SR39 D2 and claims CAP_D3D.

V9XDDP, the Direct3D battery SiS's own HAL was run through on 2026-10-04,
is the exit gate.

## Measured

**Boots 212 and 215: the machine froze, twice, at the same step.**
V9XDDP's step log ends both times after a DDBLT_DEPTHFILL, before it reads
the Z surface back. The fault trace from boot 215 shows why it froze:
- 89 idle timeouts on the 2D engine (82A8h D30, "busy or queue not
  empty");
- every Lock answering WASSTILLDRAWING.

V9XDDP locks with DDLOCK_WAIT, which retries for ever. The machine was
alive, spinning. Before that, every textured draw after the first read
black: refused at the opening 2D wait.

**Boot 217: the first fault was a 3D stall.** With the engine invalidated
on a timeout (below), the first fault of the boot was a 3D idle timeout,
with 89FCh reading 00200074h. A healthy engine reads 002000FFh. V9XDDP
completed.

**Boot 218: the stalled stream.** The engine logged its last two batches
on that timeout:
- batch 26: untextured, SRCALPHA/INVSRCALPHA;
- batch 27: the first textured batch, a 64x64 ARGB1555 COPY.

Batch 27's triangle drew; the wait after it never ended.

**Boots 216 and 219-227: the probe reproduces it, and the control does
not.** SIS3D replayed the logged words with the bases moved to 3 MiB, and
sent no 2D command:

| Before batch 27 | Result |
|---|---|
| nothing (also V9XDDP's first three textured draws in a row, boot 216) | idle |
| batch 26 (blend), texture far from the target | **stall** |
| an untextured batch without blend | **stall** |
| batch 26; batch 27's texture words before its enable | **stall** |
| batch 26, then enable 800h, ONE/ZERO, an idle wait | **stall** |
| an untextured batch with the texture-cache bits on | **stall** |
| an untextured batch; batch 27 without large cache or bit 15 | **stall** |
| an untextured batch with perspective on | **stall** |
| the same batch drawn textured, colour mode Cpix | idle |

Every stall left 89FCh at 00200074h, the value phase 3's run A left.

**Boot 228: the workaround.** Untextured draws were drawn textured, with
colour mode Cpix and vertex alpha. V9XDDP completed:
- 99 checks pass on both this engine and SiS's HAL.
- The 4 checks only SiS passes are specular and fog, which this engine
  refuses.
- This engine also passes `PerspOk`, `MipLadderShapeOk` and
  `TexMatrixCountsOk`, which SiS's HAL failed.
- The live snapshot read 0 idle timeouts.

The step log (`B228-V9XDDT.TXT`) holds the tests SiS's baseline never
reached. In total, 200 Ok keys pass and 21 fail.

- **Depth, through the SiS engine, passes.** These tests never ran under
  SiS's HAL:
  - `ZDepthFillOk=1`: fills of 1234h, then ABCDh, read back at the origin
    and the corner;
  - the second-stage `D3DZCompareOk=1` and `D3DZWriteMaskOk=1`.

  The first-stage `D3DZ*` keys hold V9XDDP's not-run marker.
- **Expected failures:** four for specular and fog, and `BlendMultiplyOk`
  (DESTCOLOR, refused).
- **SiS's HAL fails these too:** `MipTriDegradedOk` and the `Mixed*`
  keys.
- **Open:** `FlipPixelOk`, `RampOk`, `SpriteOk` and the four
  `Spr_zon_*` cells (sprites with Z on).

## What this settles

1. **A batch drawn with texturing off, followed by a textured batch,
   stalls the engine.**
   - The textured triangle draws, and the engine never reports idle.
   - Nothing short of a reboot recovered it: SR39 off and on did not
     (textures record).
   - Blend, write order, the cache bits, perspective, an intervening idle
     wait and the texture's placement made no difference.
2. **The driver never draws with texturing off.** An untextured draw is
   drawn textured:
   - colour mode Cpix and vertex alpha;
   - a 1x1 RGB565 texel at the target's own offset, which the blend
     ignores;
   - perspective off, so an untextured vertex's RHW is not read.

   Untextured results go through the Cpix path. Phase 2 measured them
   untextured; V9XDDP's untextured checks pass this way.
3. **Phase 3's run A hang was this.** It came on boot 210, after phase
   2's untextured runs; its first textured draw stalled. The textures
   record put it on D4 held with level field 0, and said that the
   combination was not repeated. It was not the cause: the reboot that
   followed drew nothing untextured before texturing, and every later
   textured scene ran clean.
4. **"Hard lock" was a freeze in a retry loop.** A stuck engine made Lock
   answer WASSTILLDRAWING, and DDLOCK_WAIT spun for ever. Both engines now
   give up on a timeout:
   - the descriptor is invalidated;
   - DirectDraw falls back to the CPU;
   - the drain completes;
   - the first fault of the boot is written through to `V9XTRACE.INI`,
     and for a 3D stall the last two batches to `V9XSIS3D.TXT`.

## Not established

- **Why the engine stalls.** The datasheet says nothing on switching
  texturing off and on. Only the state was varied: the Cpix workaround is
  measured; the mechanism is not.
- **Whether the stall needs the untextured batch to draw.** Every variant
  drew a triangle. An empty one was not tried.
- **Specular and fog:** refused, and not measured.
- **Why `FlipPixelOk`, `RampOk` and the sprite-with-Z cells fail.** The
  step log has their raw values; they are not yet read.
- **Throughput.** The engine waits for idle before every triangle, as the
  probes ran, and now samples a texel for every untextured pixel.
