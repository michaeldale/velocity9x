# B10, the intel-gma package by Have Disk on the GMA 950 netbook from Windows' VGA driver: one model, no prompt, enable-ok at 640x480x8; not a machine that never had the driver

Date: 2026-11-25. Machine: the netbook (W9QI2BE2, HP Mini 110, 945GSE,
GMA 950 `8086:27AE` on PCI function 0, `8086:27A6` on function 1),
Windows 98 SE, remote agent 0.19.0, boots 369-371.

## What this run is, and is not

B10 asks for a Have Disk install on a guest or machine that never had
the driver. 86Box has no card the `intel-gma` INF claims, so the
netbook is the only Intel GMA machine this can run on, and it has run
Velocity9x since September. The run repeats the 2026-11-07 procedure
(issue [2026-11-07-first-install-stays-at-16-colours](../issues/2026-11-07-first-install-stays-at-16-colours.md),
then with 0.39.0): put function 0 back on Windows' driver, then install
the released package the way the package's INSTALL.TXT says. What it
leaves on the machine from earlier installs, and a fresh machine would
not have:

- the old Velocity9x INF in `C:\WINDOWS\INF\OTHER` (Update Driver listed
  "Velocity9x Intel GMA 950 (945GSE) (11-7-2026)" before Have Disk);
- the Velocity9x files in `C:\WINDOWS\SYSTEM` and `C:\V9XDIAG`;
- the Display property-sheet handler key, registered by hand on
  2026-10-04. It was not read between the switch to VGA and the
  install, so whether the install wrote its Tag is not known.

So this settles the install wizard, the files and the first boot on
this chip. It does not settle the Display Properties tab on a fresh
Intel machine, nor anything about the Eee PC reports.

## Before

Boot 369: a 0.61.0 dev set (`ac9aa76b-dirty` in the version resources),
`Stage=enable-ok` at 1024x576x16. The eight SYSTEM files were copied to
the session scratchpad before anything changed.

## Back to Windows' driver (boot 370)

Device Manager, Display adapters, "Velocity9x Intel GMA 950 (945GSE)",
Driver, Update Driver, "Display a list...", Show all hardware,
(Standard display types), "Standard PCI Graphics Adapter (VGA)"
(`MSDISP.INF`). Windows set `HKCC\Display\Settings` to
`BitsPerPixel=4`, `640,480` before the restart, as on 2026-11-07. The
restart prompt was declined and the agent's `reset` used. Boot 370
came up at 640x480 on `vga.drv`; Display adapters listed "Standard PCI
Graphics Adapter" (function 1) first and "... (VGA)" (function 0)
second. `V9XBOOT.INI` was not rewritten (identical to boot 369's).

## Released 0.60.0 by Have Disk (boot 371)

`releases/0.60.0/velocity9x-0.60.0-intel-gma.zip`, SHA-256
`0A988BC5...` matching `SHA256SUMS.txt`, unpacked on the host and
copied to `C:\V9X060I`. On function 0 ("... (VGA)"): Update Driver,
"Display a list...", Have Disk, `C:\V9X060I`.

- Have Disk offered one compatible model, "Velocity9x Intel GMA 950
  (945GSE)". Windows copied the files with **no prompt for
  `V9XDISP.DRV`** and asked to restart.
- After the copy, before the restart: `BitsPerPixel=8`, `640,480`; no
  `WININIT.INI`; RunOnce empty.
- First boot (371): `Stage=enable-ok`, `DriverInitResult=ok`,
  `VbeDetail=ok`, 640x480x8, `Adapter=Intel GMA 950 (945GSE)`,
  `Direct3D=hardware-gen3`. **No 16-colour first boot.**
- Display Properties showed the Velocity9x and Velocity9x Advanced tabs;
  the handler's `Tag` (`0x3A46552E`) was the same before and after it
  opened.
- The package's `V9XMSW /set:1024x576x16` passed; the desktop drew at
  the panel's native mode.

## Two files were not replaced

Six of the eight SYSTEM files matched the zip by SHA-256 after the
install. `GLIDE2X.DLL` and `GLIDE3X.DLL` were still the 0.61.0 dev
copies. All eight old files carry version 0.61.0.0 and all eight new
ones 0.60.0.0, and the INF copies them in one `CopyFiles` section with
no flags, so a newer-version rule does not explain why only the two
Glide DLLs were kept. Not investigated. A user going from an older
release to a newer one does not meet this case; a user stepping back
from a newer build would run a mixed set without being told. The two
released files were then put in place by the agent (hashes match), so
the netbook now runs released 0.60.0 throughout. The game-folder
`GLIDE2X.DLL` copies (NFS II SE, Carmageddon II) were not touched.

## Not done for B10

`nvidia`, `sis` and `3dfx` need physical cards that have never had the
driver, and the release candidate's zips do not exist yet. `intel-gma`
on a machine that never had the driver remains owed; this run is the
nearest the available hardware gives.
