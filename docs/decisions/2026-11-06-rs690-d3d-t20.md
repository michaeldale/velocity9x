# V9XD32 T20: fog, ADD, DECALALPHA and colour key through the HAL

Date: 2026-11-06. Machine: M-GB8KRE (RS690 1002:791F, Win98 SE, DirectX
6.1). Build: branch `ati-rs690`, 1c390bce-dirty. Captures:
`docs/probe/rs690-d3d-t20-2026-11-06/`.

## Why

Until now, fog, ADD, DECALALPHA and the source colour key on the RS690
were measured in the register probe (V9XRS3D) and host-tested in the
mapping. No Direct3D draw had reached any of them. V9XD32's existing
tests do not touch them at DDI 5, and its fog tests need DirectX 7.

## What T20 does

T20 is a new V9XD32 test, drawn after T7 in the same scene and judged
with the rest. It draws five 48x48 quads in the band y 96–143 through
DX5 render states and a DX5 texture handle:

| Quad | State | Expected at the quadrant centres |
|---|---|---|
| FogFull, x 8 | FOGENABLE, FOGCOLOR blue, specular alpha 0 on red | 0000FFh |
| FogHalf, x 64 | the same at specular alpha 80h | 80007Fh |
| Add, x 120 | T6's ARGB1555 quadrant texture, ADD over diffuse 004040h | FF4040h (red), 0040FFh (blue) |
| DecalAlpha, x 176 | ARGB1555, left quadrants alpha 0 and right alpha 1, DECALALPHA over blue | blue on the left, the texels on the right |
| ColorKey, x 232 | RGB565 quadrants keyed (SetColorKey SRCBLT) on green 07E0h, DECAL, over a grey quad | grey where green was, red/blue/white |

Each point must be within 8 per channel, T6's tolerance. A refused draw
leaves the clear colour and fails. T20 counts toward Failures.

The number T16 was already taken by the DirectX 7 test, and T17–T19 are
taken too.

## Results

| Run | T20Ok | Failures |
|---|---|---|
| HAL, 32 bpp (boot 74) | FFFh, all 12 points | 0 |
| HAL, `/bpp16` (boot 74) | FFFh | 0 |
| software renderer (`[Velocity9x] Direct3D=2`), 32 bpp (boot 75) | D00h | 8 |
| software renderer, `/bpp16` (boot 75) | D00h | 8 |
| HAL again after SYSTEM.INI was restored (boot 76) | FFFh | 0 |

So all four features draw correctly through the RS690 HAL at both
depths. At 32 bpp every point is exact (FogHalf 80007Fh).

The software renderer gets none of them: it draws no fog, ADD and
DECALALPHA come out black, and the key colour shows. It is not a
reference for these states on this path. The expected values come from
Direct3D's own definitions:

- vertex fog: f × colour + (1 − f) × fog colour, f the specular alpha;
- ADD: colour = texel + diffuse, alpha = diffuse;
- DECALALPHA: blend from diffuse to texel by the texel's alpha, alpha =
  diffuse;
- colour key: drop the source-key colour.

The software run does show that T20 discriminates: a renderer that lacks
the states fails it. Its other failures (T9, T11, the soft engine's
CULLNONE) are as recorded in 2026-11-03.

## Consequence for other chips

V9XD32 is the release checks' Direct3D gate. Any engine that refuses or
mishandles one of these states will now fail T20 and report Failures ≠ 0.
For example, d3d_g4.c takes ADD only on textures without alpha, and
T20's ADD texture is ARGB1555. Run V9XD32 on each release-check machine
before this test reaches main, and either fix the engine or record the
failure.
