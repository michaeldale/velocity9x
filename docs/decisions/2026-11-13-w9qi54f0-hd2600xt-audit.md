## What it settles

- **The card is the one the owner named.** The live devnode is
  `PCI\VEN_1002&DEV_9588&SUBSYS_216C1458&REV_00`, bound to the tier-0
  VBE driver. `V9XHW.INI`: `PciVendorId=1002`, `PciDeviceId=9588`,
  `Acceleration=none`, `Direct3DMode=software`, `ScreenShadow=on`.
- **Velocity9x has no R600-generation entry.** The `ati` family lists
  Mach64, Rage, Rage 128, RS690 (`791F`), Evergreen (`68F9`, `68B8`,
  `68D9`, `6778`) and the APUs. Nothing between RS690 and Cedar.
- **VBE answers 3.0 with 16 MiB.** `VbeController=v=0300 mem=256`
  (256 x 64 KiB); the board's real memory size was not read. LFB at
  `E0000000` from BAR0, `DpmiMap=01000000:ok`. 48 modes, none above 8 bpp
  is paletted; 565 at 16 bpp, x888 at 32 bpp. The list stops at
  1920x1440 and has no 1920x1080 or 16:9 mode, so the AOC panel cannot
  run at its native width on `vbe`.
- **The BIOS covers `E0000000` with an uncachable variable MTRR.**
  `Mtrr5=e0000000 e0000800` reads as 512 MiB, type UC, by the Intel SDM
  layout. `MtrrWrite=refused`, `PatWrite=ok`. Whether the 512 MiB is the
  BAR's size was not checked (no config read).
- **DirectDraw stopped at a transient.** `V9XDDH.INI`
  `Stage=setinfo-callback-missing`, `LastGoodStage=setinfo-ok`; per
  `dd16.c:300` that pair is the retry race, not a failure. No DirectDraw
  program was run.
- Three driver loads in `V9XTRAIL.TXT` (12:50, 12:56, 14:21), each
  `enable-ok`.
- Test content on the guest: `C:\games\Q3Ademo`, a 3DMark 2001 SE
  shortcut. `C:\DRIVER` holds a stock pile of third-party INFs, none for
  ATI.

## Not measured

  devnode's instance (`000800`) puts the card behind a bridge; which one
  was not read.
- Any RV630 register (BAR2 MMIO), the real VRAM size, EDID.
- Whether DirectDraw or Direct3D work at all on this machine's `vbe`.
- Installed RAM above the 2 GiB Windows reports.

## What it would take

RV630 is the R600 generation: AVIVO display (the RS690 tree drives
AVIVO CRTCs), and a shader-only 3D engine fed by a CP with microcode
(the Evergreen trees' approach, an older register map). Neither existing
tree covers it as is. A plan belongs in `docs/plans/` before any probe;
the first step would be the same read-only PCI and MMIO survey the RS690
started with.
