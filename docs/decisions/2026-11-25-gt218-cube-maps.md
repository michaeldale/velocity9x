# GT218 cube maps and signed formats: a tiled copy of each cube, a cube fetch that does not divide by the major axis, and Q8W8V8U8 and V8U8 as SNORM; T19 passes

Date: 2026-11-25. Machine: W9QI0DAD (AMD FX-6300, Windows 98 SE), ASUS
GeForce 210, GT218 `10DE:0A65`, `nvidia` package, desktop 1024x768x16,
boots 144-147. Step 6 of [nvidia-gt218-ps11.md](../plans/nvidia-gt218-ps11.md):
the cubes first, then the signed Q8W8V8U8 and V8U8 formats (the Normal
row), at the end.

## Before

The core claims cube maps on this engine because it has `draw_shader`
([2026-11-15-gt218-draw-shader-ddi8.md](2026-11-15-gt218-draw-shader-ddi8.md)),
but nothing placed or sampled one:
- `create_surface` took a cube's six chains as one malformed mip chain
  and left them to DirectDraw;
- the HAL's cube refusal could never fire, because the core passes
  `env.cube = 0` (the engine is meant to know a cube by where it placed
  it), so a cube stage was sampled as a 2D texture.

V9XD32 T19 Cube was wrong on every pixel (1,053), as at 0.53.1.

## The change

- **Placement** (`v9x_d3d_nv50_create_cube`, `d3d_nv50.c`). A
  video-memory cube is placed as one heap block. The runtime's list is
  six faces, each its top then its levels, faces named in DDSCAPS2, with
  +X's top first.
  - The linear part holds every surface level-major, each level's rows on
    64 bytes and each face on 256, as every texture here, for the
    runtime's Locks and Blts.
  - The tiled part holds level 0's six faces as layers.
  - Each part starts on a row-block unit of its own
    (`v9x_nv50_rblock_place`), as a Z buffer and its colour shadow do.
  - A 64-slot table knows each cube by its +X top. Destroying the +X top
    frees the block, with its release window as a Z buffer's.
- **Tiled layout** (`v9x_nv50_d3d_cube_layout`, `nv50_d3d.c`). Tile mode
  10h. Rows on the 64-byte GOB, height on 8-row blocks, and each layer one
  face rounded up to the 512-byte tile: Mesa's `nv50_miptree.c` layer
  stride for one level.
- **The copy** (`v9x_d3d_nv50_cube_copy`). Before a draw samples a cube
  that was created or written since (Blt or Unlock, `surface_written`), the
  six faces' level 0 go to the tiled layers. That is one 502D copy each,
  through the kind-70h window, in one kick: A8R8G8B8 for 32-bit texels,
  which keeps the top byte, and R5G6B5 for 16-bit, the same 16 bits
  whatever the format.
- **The TIC** (`v9x_nv50_d3d_tic_cube`). The pitch TIC is turned into
  Mesa's `nv50_tex.c` block-linear cube for the NV50 class: CUBEMAP (C000h)
  with no LAYOUT_PITCH, the tile mode at word 2 bits 22 up, word 3 300000h,
  word 4 bit 31 with the width, depth one cube, last level 0, word 6
  3000000h. Addressing is clamped. Only level 0 is sampled, as for every
  texture on this path.
- **The shader path** (`draw_shader`). A stage whose texture is a placed
  cube samples its copy. The stage goes into the translator's `desc.cube`
  and the program cache key. A texm3x3 lookup into a cube stage is drawn;
  into anything else it would be a 3D fetch and stays refused.

## First run: the fetch does not divide

Boot 145, the build with all of the above. T19 Cube: 986 of 1,053 pixels
wrong, worst channel 99, against 223 before. V9XD32 gained a pixel dump
for this (`C:\V9XDIAG\T19DUMP.INI` `[T19Dump] Row=`, every judged pixel's
got, want and set-1 direction to `V9XT19D.TXT`;
`cube-dump-unscaled/`). Each colour was decoded back to the face and
texel T19 writes (red face × 40 + 20, green x × 32 + 16, blue
y × 32 + 16):

- **Faces:** the face was right on all 1,053 pixels, so the layer stride
  and the face selection are right.
- **Texels:** x was right on 306 and y on 300. The texels sampled
  clustered towards each face's centre (on face 1, wanted x 0 to 3 all
  came back 3). They were not a fixed permutation of the wanted ones, so
  this is not a swizzle mismatch between the 2D engine and the sampler.
- **Fits** of the face coordinate s = (sc / D + 1) / 2 for divisors D of
  the direction:

| D | Pixels matching what the GPU sampled |
|---|---|
| \|ma\| (the reference, and Direct3D) | 67 |
| \|d\| | 227 |
| 2 \|ma\| | 618 |
| **1 (no division)** | **1,049** |

So the GT218's cube fetch takes each face coordinate as already projected
and does not divide by the major axis. `nv50_ps11.h` had said, unmeasured,
that Mesa passes the direction unscaled and that no division was needed.
The host model of NV50 programs (`test_nv50_ps11.c`) divided in its own
sampler, which is how the translator passed it.

**Fix** (`nv50_ps11.c`, `v9x_nv50_ps11_lookup`): before a cube fetch,
m = max(|x|, |y|, |z|) (two `fmax` with the absolute modifier), r = rcp(m),
then each coordinate times r. The model's sampler now passes a cube's
coordinates as given, which is what the GPU does; its cube cases failed
with the old translator and pass with the fix.

## The signed formats, the same evening

The rest of step 6: Q8W8V8U8 and V8U8, which the core publishes where
pixel shaders run (T19 Normal samples an 8×8 Q8W8V8U8 normal map).

- **Recognition** (`v9x_d3d_nv50_format_of`): by D3DFORMAT under
  DDPF_D3DFORMAT or DDPF_FOURCC, and V8U8 also by DirectX 7's
  DDPF_BUMPDUDV with U in the low byte, as `v9x_d3d_vi_signed_format`
  does. The engine now places them (DirectDraw cannot size Q8W8V8U8,
  which comes with no bit count).
- **TIC** (`v9x_nv50_d3d_texture`), Mesa's `nv50_formats.c` rows:
  - Q8W8V8U8 as R8G8B8A8_SNORM: A8B8G8R8 sizes, SNORM (1) in all four
    data types, R G B A to X Y Z W, so U V W Q in memory order;
  - V8U8 as R8G8_SNORM: G8R8 sizes, R G to X Y, then zero and one, as the
    Oland and the HD 4600 read it. No test reads V8U8's blue or alpha.
- **The fixed-function map** refuses both; the core draws such a stage
  through `draw_shader`, whose unit takes them.
- Host tests first, seen failing (7 checks): the TIC words in
  `test_nv50_d3d.c`; the fixed-function refusal and the shader unit in
  `test_d3d_nv50_map.c`.

Boot 147, `run-release-checks.ps1` (8 of 8): **T19 passes**. Normal 0
mismatches (worst channel 8), Cube 0 (8), and Bem, FfBem and FfBem3 still
pass (9 each); the FfBemL rows skip, since no luminance op is claimed.
V9XGLP, V9XGLIDP, V9XR3DP, V9XWPRS and V9XFBCMP pass. V9XD32's
`Failures` is now 1, and that one is T20, the fixed-function test whose
pass mask `T20Ok` reads F203h here as it did at 0.53.1. It is not
touched by this work.

## Not done or not measured

- L6V5U5 and X8L8V8U8 (BUMPENVMAPLUMINANCE): not claimed, as the plan
  allows until the FfBemL rows can be judged.
- Cube mip levels other than 0, and a cube's levels in a game.
- 3DMark 2001 SE with cubes, at 32 bpp.
- Copies are made per draw that samples a dirty cube, which is all of
  them for a cube rewritten every frame. The cost is not measured.
