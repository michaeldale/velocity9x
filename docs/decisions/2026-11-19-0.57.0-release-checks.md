### M-D7TFW4: the failures are the machine, not 0.57.0

Trinity's failures are not caused by this release. At 08:07Z the owner
wrote in the remote-help chat that they had fitted the HD 7470 into this
PC; boots 81 to 84 happened without us. 0.56.1 passed every check on the
HD 7660D earlier the same day. To separate the driver from the machine,
the released 0.56.2 `ati` package (build 593a7890) was installed by the
same runner (boot 86 to 87,
[`trinity-0.56.2-control/`](../probe/0.57.0-release-checks-2026-11-19/trinity-0.56.2-control/)).
It failed the same way: V9XD32 default and bpp16 left no final report,
stopped at T17 with T13, T4Flat and T16 failing and the Direct3D 8 HAL
caps returning 8876086Ah, V9XGLP failed Cva, V9XGLIDP was incomplete, and
the agent dropped offline mid-run. The 0.57.0 changes do not reach the
Evergreen D3D path except the flip hold rule, which this run reproduces
without. Trinity is not counted as checked for 0.57.0; which adapter the
machine now drives was not established.
