# RIVA 128ZX: no 32-bit textures, and the 8888 checks stay failed

Date: 2026-11-04

Machine: M-7V636C (remote help), RIVA 128ZX 8 MiB, boot 32 (b5d1e2ba).
File: `docs/probe/m7v636c-riva128-games-2026-11-04/b32-V9XDDT.TXT`.

## What V9XDDP reads

Tex8A8888HalvesOk and Tex8X8888HalvesOk are 0. The 8x8 ARGB8888 and
XRGB8888 surfaces are created (SurfaceHr 0, pitch 256): the HAL does not
recognise the formats, so DirectDraw places them itself. Every draw from
them is refused for its texture (policy slot 3), so both halves read 0.

## Why it stays

The D3D object samples A1R5G5B5, X1R5G5B5, A4R4G4B4 and R5G6B5 and
nothing wider (nv3_3d.xml), and the HAL lists only its three 16-bit
formats, so an application choosing from the list never asks for 8888.
Gen3 (Pineview, GMA 900, the 0.28.0 netbook checks) and the 86Box Mach64
VT2 read the same two checks as 0 for the same reason; the SiS 6326,
which samples 8888, passes them.

A converted copy (ARGB8888 as A4R4G4B4, XRGB8888 as R5G6B5) would pass
them by quantising an application's texels without saying so, for the
test's sake alone. Michael's call, 2026-11-04: record and move on.
