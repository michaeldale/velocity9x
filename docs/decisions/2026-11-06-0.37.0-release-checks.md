# 0.37.0 release checks: five machines, four packages, probes only

Date: 2026-11-06

Status: measured on five machines on `55a661a2` from a clean tree:
`Build=55a661a2` in every probe report, and every installed file's
SHA-256 matching the package. `run-checks.ps1` passed and the four
probes (V9XD32, V9XGLP, V9XGLIDP, V9XR3DP) were rebuilt first. Michael
asked for probes only this time, so no games ran. The RS690 itself was
checked separately on `e5f3a34f`, whose source tree is identical to
`55a661a2`'s (`2026-11-06-rs690-0.37.0-checks.md`).

0.37.0's change is the RS690 on the ati package. That merge also added
RS690 code to the mini-VDD source every family is built from
(`loader.asm`), and RS690 dispatch hooks to the shared Direct3D and
scanout code. So every package changed, not only ati.

Evidence: [`../probe/0.37.0-release-checks-2026-11-06/`](../probe/0.37.0-release-checks-2026-11-06/),
one folder per machine. The `-before` folders are the same probes on
the driver each machine had before the swap.

## What failed, and whether 0.37.0 caused it

- **Rage 128 Pro, T4Flat and T16.** Not the driver. The same V9XD32
  fails them on the 0.36.0 build too (boot 669). The V9XD32 built from
  0.36.0's source (`5d95df34`) passes on this 0.37.0 driver: Failures
  0, T4Flat EXACT, T16 PASS. The new T20/T21 tests leave the card
  where T4's Clear returns E_NOTIMPL. Filed:
  `docs/issues/2026-11-06-v9xd32-t20-t21-break-t4-t16-on-rage128.md`.
- **RIVA 128ZX, T21.** The same on the driver before the swap. Mip
  levels below 8x8 are not drawn (T21Ok 7), a known RIVA limit that
  T21 now counts.
- **RIVA 128ZX, Glide.** 14 failures on 0.37.0 against 1 (Line) on the
  driver installed before. Clears and flips pass; no triangle draws. A
  regression against that build. Whether 0.36.0's package already
  behaves this way is not known: the build at boot 39 was not
  identified. Filed, to review in a later release (Michael):
  `docs/issues/2026-11-06-riva128-glide-draws-nothing-on-0.37.0-candidate.md`.
- **vbe (1002:9854).** Every result is the same before and after the
  swap.

## Incidental

- **HD 4600, 3DMark 2000.** The run queued after the probes did not
  start. MPREXE.EXE had faulted, a general protection fault in
  USER.EXE at 0004:1E66, and its dialog covered 3DMark's menu.
  Nothing links it to the driver; it was not rerun.
- **Rage 128 Pro, 3DMark 2000 default, grabbed.** Scored 1009 (0.36.0:
  1122 ungrabbed). Its ten Game 1 frames show terrain, haze, sky, smoke
  and HUD (`rage128/3dmark2000-grab/grabs-sheet.jpg`).
