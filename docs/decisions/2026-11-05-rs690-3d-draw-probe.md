# RS690 3D engine draws by register writes, no CP

Machine: M-GB8KRE (Sempron 210U, Radeon X1200 IGP 1002:791F, Win98 SE),
on the branch `ati` driver (13103c2d-dirty, boot 56). Probe `V9XRS3D.EXE` +
`RS3D.VXD` from branch `ati-rs690` at 6c3ef3d9 plus this work
(`6c3ef3d9-dirty`). 2026-11-05 ~04:20Z. Captures in
`docs/probe/rs690-3d-2026-11-05/`: the result file per mode and each test's
4 KiB read-back surface (`R3Q` quad, `R3T` triangle, `R3G` Gouraud, `R3F`
2D fill after).

## Question

Phase 5 of `docs/plans/ati-rs690-x1200.md`: does the R300-class 3D core
draw when every register is written directly over BAR2, with the CP off and
no microcode, using xf86-video-ati 6.14.6's `RADEONInit3DEngine` and its
MMIO composite path, plus Mesa r300's routing of a per-vertex colour into
the fragment shader (the X driver only draws textured quads)?

## What ran

`src/chipsets/ati/rs690/rs690_3d.c` builds every value; its host test was
written first and failed against a stub. Init: 64 writes once (tiling for
one pipe, VAP in PVS bypass, the scan converter's 1440 guard offset). Per
draw: 30 writes of colour-buffer state (position FLOAT_2 + colour FLOAT_4
streams, one colour interpolator into temp 0, a one-instruction shader
`out = temp0 * 1 + 0`, blending off), `VAP_VF_CNTL` and six dwords per
vertex to `SE_PORT_DATA0`, then the finish (3D cache flush, `WAIT_UNTIL`
3D idle-clean). Every batch of at most 16 writes waits for that many free
FIFO entries first; a wait that runs out stops the op list.

Target: a 64-pixel-wide surface at frame buffer offset 16 MiB, prefilled
with A5h.

## Measured

| | 640x480x16 | 1024x768x32 |
|---|---|---|
| Quad (quad list, flat magenta, integer corners): bytes off | 0 | 0 |
| Triangle (flat green): inside wrong / outside wrong | 0 / 0 of 242 | 0 / 0 of 242 |
| Gouraud (red, green, blue corners): inside wrong / outside wrong | 0 / 0 | 0 / 0 |
| Gouraud worst channel error, steps | 0.66 (5/6-bit) | 0.59 (8-bit) |
| 2D fill after the 3D tests: bytes off | 0 | 0 |
| Edge-band pixels drawn | 46 of 96 | 46 of 96 |

Pixels whose centre lies within one pixel of the slanted edge are not
judged. The Gouraud error is measured against interpolation at the pixel
centre (x + 0.5, y + 0.5); under 0.7 of a step at both depths says that is
where this rasterizer samples. Every wait finished in 2 to 9 status reads;
`RBBM_STATUS` read 10000140h before and after, the engine idle.

Before the first init, `GB_TILE_CONFIG` read 46FB5D5Eh, an unprogrammed
value: VBE leaves the 3D core alone. `GB_PIPE_SELECT` read 00000100h, one
pipe, as the register probe found. `VAP_CNTL_STATUS` kept bit 19 set
(00080000h before, 00080100h after the bypass bit was added); neither
source names bit 19.

## Followed where the sources differ

`VAP_VTX_STATE_CNTL` 5555h and `VAP_VSM_VTX_ASSM` position | colour are
Mesa's; the X driver writes 0 and nothing, but never sends a colour. The
colour arrived, so Mesa's values work here. Whether the X driver's also
would was not tried.

## Not checked

- Textures, Z, blending, alpha test, culling and fog: none of it ran.
- 8 bpp: the colour buffer has no palette format; refused by the builder.
- Throughput. A triangle is 1 + 18 MMIO writes after the state; what PIO
  costs against the software engine on this CPU is still open.
- Larger or many primitives in one `VF_CNTL`, and long runs.
- A DOS box or mode set between draws.
