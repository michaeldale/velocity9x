# GMA 900 on 949fc64b: the moved-ring build reads as before, and the boot stall was the boot menu

Date: 2026-10-20. Machine: Tom Rossell's Acer (915GM, GMA 900 `8086:2592`),
remote help `M-NGMX0T`. Build `949fc64b` (0.21.1, after the Pineview
Phase 1 commit `bce8b693` and the renderer-name fix). Evidence:
`docs\probe\tommo33-gma900-949fc64b-2026-10-20\`.

This is the second Gen3 part on the Phase 1 code, which reaches every
Gen3 chip:
- the ring opens at the reserve the heap was computed from, which on this
  part is `0x6B0000` as before;
- the descriptor refuses while the VBE size is unread.

## Install and the stall

`V9XDISP.DRV`, `V9XMINI.VXD`, `V9XHAL.DLL`, `V9XGL.DLL` and `V9XSETP.DLL`
were staged at 8.3 names in `C:\`. A rename-only `WININIT.INI` (no `NUL=`)
swapped them in at one agent reboot.

- The agent accepted the reboot at 21:11:22 (`AGENT-2026-10-20-restart.LOG`, boot 4).
- It did not check in again until 21:29:29 (boot 5), after Tom
  power-cycled the machine.
- Michael relayed from Tom that the machine had stopped at the Windows
  boot menu. It was not a driver fault.
- The rename had run: `WININIT.INI` was gone, and all five installed files
  had the package's sizes.
- `BOOTLOG.PRV` ends in a clean shutdown sequence, and `BOOTLOG.TXT` is the
  power-cycled boot.
- That boot reached `enable-ok` (`V9XBOOT.INI`).

## Mode-set state and video BIOS (same boot, later)

V9XTRACE built from `6377f101` with two additions:
- the live pipe's clock and panel registers;
- an opt-in `-vbios` image of `C000:0000`.

It was run as `V9XTRC2.EXE -vbios` (`V9XSNA7-clocks.INI`). `BuildsAgree=0`
is expected: this trace build carries its own id. Read-only:

| Register | Value |
|---|---|
| Live pipe | B |
| `DPLL_B` | `0x98026000` |
| `FPB0` / `FPB1` | `0x00041309` / `0x00031108` |
| `PP_STATUS` / `PP_CONTROL` | `0xC0000008` / `0x00000001` |
| `PP_ON_DELAYS` / `PP_OFF_DELAYS` / `PP_DIVISOR` | `0x00C807D0` / `0x01900FA0` / `0x00270F04` |
| `BLC_PWM_CTL` | `0x00000000` |

The image is kept outside the tree, since the repository is public and the ROM is Intel's and Acer's, in `claude\personal\v9x-testers\tommo33-2026-10-20\vbios\gma900-acer-915gm-V9XVBIOS.BIN`, SHA-256 `7c2d47a106fb30e0d9ae0ba282cac104169cbb7f6c9cc86da0187c8565c2f382`. It is the 61,952-byte image (header says `0xF200`), signature
`AA55`. It contains `$VBT` and `BIOS_DATA_BLOCK`. These words are the
inputs a driver mode set would decode; they are recorded, not decoded,
here.
