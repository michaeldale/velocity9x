# B9 on the Oland R7 250: Stand By and resume come back to the desktop, slowly, on our driver and on Windows' own; the first run's "hang" was not shown to be one

Date: 2026-11-25. Machine: W9QI0DAD (AMD FX-6300, Gigabyte SB700
board, Award BIOS 11/25/14), Windows 98 SE, Radeon Oland XT
`1002:6610`, boots 137-141. Power management is **APM**
(`Enum\Root\*PNP0C05`, VPOWERD with `SuspendFlag=1`, no ACPI
enumerator). Stand By is offered in the Shut Down dialog. Michael woke
the machine each time by key or mouse, watched the monitor, and
power-cycled after the first run. OBS captured the card's HDMI
throughout (`obs/`).

B9's acceptance is one laptop. This is a desktop, so it does not meet
B9; it is the first resume on real Radeon silicon, where the card
can lose power, which 86Box cannot show.

## Runs

| Run | Driver | Into Stand By | After the wake |
|---|---|---|---|
| 1, boot 137 | Velocity9x `ati` (B6 fix set) | agent silent within 25 s; the desktop stayed on the HDMI (6:31 PM, unchanged) | Michael: "locked up with desktop displayed". **The agent was not asked.** Power-cycled. |
| control, boot 139 | Windows' "Standard PCI Graphics Adapter (VGA)", 640x480x4 | agent silent; HDMI signal off (OBS's no-signal bars) | screen back; the agent answered (clock 7:00 to 7:07), took screenshots and opened the Start menu by injected input; the hourglass showed; Michael: "it is awake, maybe just slow" |
| 2, boot 141 | Velocity9x `ati` from main by Have Disk (`2c432932-dirty`, the code of `e6e14b2a`) at 1024x768x32 | agent silent within 25 s; the desktop stayed on the HDMI (7:12 PM) | Michael first: "screen is away but won't wake up"; the agent answered (boot 141), the hourglass on the HDMI, then the Start menu opened on the HDMI as through GDI (7:14 PM); Michael: "seems working" |

After run 2's resume, with no restart: V9XWPRS `PASS` (a DirectDraw
program after the resume, as the acceptance asks), V9XD32
`Failures=0` (T19 included), V9XFBCMP `PASS` (the frame buffer equals
GDI's shadow). The mode stayed 1024x768x32.

## Reading

- **The resume works on this board with both drivers. It is slow, by
  minutes, and the machine looks dead while it comes back.** Run 1 was
  power-cycled before anyone asked the agent. Its evidence, a
  `V9XTRAIL.TXT` with nothing after the last mode set, fits a hang and
  a slow resume alike, so run 1 is not counted as a hang. Run 2, with
  the same driver and the same procedure but given time, came back.
- **Where the time goes is not measured.** On the VGA control the
  physical keyboard and mouse seemed dead at first while injected input
  worked, which points at the input devices or the APM BIOS rather
  than display. Nothing of ours was loaded in that run.
- **Our driver leaves the monitor lit in Stand By; Windows' driver
  turns it off.** That is the 2026-08-11 decision
  ([record](2026-08-11-monitor-power-management.md)): every family but
  `s3` and the Mach64 reports monitor D0 only
  ([2026-11-24](2026-11-24-standby-monitor-power-s3-ati.md)). It is not
  a fault, but it is a difference a user will notice.
- **Nothing of ours ran at the resume** as far as the trail shows: no
  `enable-start` or mode set near the wake in run 2. The trail does
  have a `libmain` … `enable-ok` block stamped 19:12:15.98, out of order
  in the file (before boot 141's own 19:11:43 entries). It is not
  explained.
- So the gap in the 2026-11-06 issue (nothing restores the mode after a
  resume) did not bite here: the card kept its mode, or the BIOS gave it
  back. Whether a laptop's resume cuts the card's power, and whether the
  mode survives that, is still the B9 question.

## Also done

The control needed the driver changed twice through Device Manager: to
`MSDISP.INF`'s VGA, then back by Have Disk from main's `ati` package in
`C:\V9XATIP`. Have Disk offered one model, "Velocity9x AMD Radeon Oland
XT" (before this the device was registered as "VBE-generic" with the
`ati` files renamed in), copied with no `V9XDISP.DRV` prompt, and boot
141 came up `enable-ok` at 640x480x8. The HAL, display driver and
mini-VDD match the package by hash. The desktop was set back to
1024x768x32 by V9XMSW, and `VSync=2` survived in SYSTEM.INI.
