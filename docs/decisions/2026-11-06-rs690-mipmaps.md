# RS690: mipmaps, in the layout the sampler was measured to read

Date: 2026-11-06. Machine: M-GB8KRE (RS690 1002:791F, Win98 SE).
Build: branch `ati-rs690`, 1968df8a-dirty. Captures:
`docs/probe/rs690-mipmaps-2026-11-06/`. The `~`, `#` and `!` captures
are saved as `tilde`, `hash` and `bang`.

## Decision

The HAL samples mip chains instead of the base level alone, and publishes
MIPNEAREST, MIPLINEAR, LINEARMIPNEAREST and LINEARMIPLINEAR.

- **Builder:** `struct v9x_rs690_3d_texture` gains `levels` and
  `mip_filter`. The highest level goes in TX_FORMAT0 bits 29:26 and the
  mip filter in TX_FILTER0 bits 14:13 (1 nearest, 2 linear; Linux
  r300_reg.h). A mipmapped texture **clears TXPITCH_EN**, its base pitch
  must be the chip's own, and the whole chain must lie in the frame
  buffer.
- **Layout:** `v9x_rs690_mip_pitch` and `v9x_rs690_mip_offset`. Level n's
  rows are its width × bytes rounded up to 64, and each level starts
  where the one before ends (stride × height).
- **HAL:**
  - Placement puts a mip chain in one block (`v9x_d3d_place_chain`) at
    those offsets and pitches.
  - The resolve walks the mipmap attachments and counts the levels found
    where the layout puts them, stopping at the first that isn't
    (V9XTRACE `D3dMipChain*`, `MipGap*`).
  - The mapping uses the chain when the minification filter is a mip
    form. DX5's names give the filter within a level, then between
    levels: MIPNEAREST nearest/nearest, MIPLINEAR linear/nearest,
    LINEARMIPNEAREST nearest/linear, LINEARMIPLINEAR linear/linear.

## The layout, measured

V9XRS3D's MipLayout tests draw a 32x16 texture's levels 0–4 1:1, so the
level of detail is exactly n, over the gradient, whose texels encode
their own address. Texels (0,0), (1,0) and (0,1) of each level read back
its offset and row stride:

| Level | 16 bpp offset / stride | 32 bpp, TXPITCH_EN set | 32 bpp, TXPITCH_EN clear |
|---|---|---|---|
| 0 (32x16) | 0 / 64 | 0 / 128 | 0 / 128 |
| 1 (16x8) | 1024 / 64 | 2048 / **128** | 2048 / 64 |
| 2 (8x4) | 1536 / 64 | 2560 / 128 | 2560 / 64 |
| 3 (4x2) | 1792 / 64 | 2816 / 128 | 2816 / 64 |
| 4 (2x1) | 1920 | 2944 | 2944 |

The offsets follow 64-byte-rounded rows with no padding between levels,
whatever TXPITCH_EN says. But with TXPITCH_EN set, every level's rows are
stepped by TX_FORMAT2's base pitch, which is wrong below level 0. At
16 bpp the two coincide only because 16 × 2 bytes rounds up to 64.

## What passed

- **MipSelect (V9XRS3D):** each level filled with its own colour at the
  builder's offsets, levels 0–4 drawn MIPNEAREST. Byte-exact at 16 and
  32 bpp.
- **MipLinear (V9XRS3D):** a 23x11 quad between level 0's and level 1's
  sizes, linear between levels, mixes red and green (FF877800h at
  32 bpp).
- **V9XD32 T21 (new):** through DX5, a 32x32 RGB565 texture created with
  DDSCAPS_MIPMAP | DDSCAPS_COMPLEX and six levels, each filled through
  the attachments, drawn MIPNEAREST at 32, 16, 8 and 4 pixels. Each
  quad's centre must be its level's colour.

| Run | T21 | Failures |
|---|---|---|
| Boot 76, the HAL before this change | T21Ok 1: red, the base, in every quad | 1 |
| Boot 77, this HAL, 32 bpp | T21Ok F: red, green, blue, white | 0 |
| Boot 77, `/bpp16` | T21Ok F | 0 |

The boot 77 snapshot (`mip77-snap.INI`) shows D3dMipChainChecks 8,
D3dMipChainLevels 6, D3dMipChainGaps 0, 3198 hardware draws and 0
refused. T20 still passes, and T15 is clean.

## Not checked

- Non-square chains through DX5. T21 is square, while the probe's chain
  is 32x16.
- LOD bias, and the level a minified triangle at a slant picks.
- Mipmaps under texture management or system-memory textures. Those are
  not placed by this engine, and their draws keep the base level.
- Like T20, T21 counts toward Failures, so other engines that do not
  sample mip levels will now fail V9XD32.
