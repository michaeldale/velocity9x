# SiS 6326 3D: textures, the pitch float, and an engine hang

Date: 2026-10-05. Machine: A8U4I5, SiS 6326 card 2 (rev 0Bh), Velocity9x
`sis` at 800x600x16, boots 210 and 211. Evidence:
`docs/probe/a8u4i5-sis6326-3d-phase3-2026-10-05/`. Plan:
[sis-6326-hardware-3d.md](../plans/sis-6326-hardware-3d.md), phase 3.
Follows [shading and depth](2026-10-05-sis6326-3d-shading-and-depth.md).

## What was run

`SIS3D.EXE /phase3` (and `/phase3a`, `/phase3m`) through `SIS2D.VXD`.
Texture state comes from the new host-tested `v9x_sis3d_build_texture`:
8A38h set, 8A3Ch blend, the level bases from 8A44h, the pitches from 8A6Ch,
and the 8A80h size.

Most scenes sample an **index texture**: 16384 RGB565 words, each holding
its own offset from the base. Under Ctex replace into an RGB565 target, each
pixel then names the word the engine fetched. Addressing, pitch, rounding
and prestep were all read from those values. Format, filter, blend and mip
scenes used purpose-built textures. Each scene covers its 32x32 target with
two triangles (or one, for prestep), with vertices shifted 1/256 px up-left
(phase 2).

## The hang (runs A and B)

The first run left 8A38h D4 ("clear texture cache") set while drawing, used
level field 0, and wrote the texture words once. **No scene went idle.**
The next run found the engine still busy at enable (89FCh = 00200074h) and
refused to draw. A reboot cleared it.

After the reboot, the probe pulsed D4: the texture words went out with D4
set, then again with it clear, as SiS's HAL leaves 8A38h. Every scene went
idle. Level field 0 alone, and D4 held alone (after a pulse), each also
went idle (run C, `Levels0` and `ClearHeld`). The combination that hung
was not repeated. The probe now stops at the first scene that fails to go
idle.

## Measured

**U and V are normalised.** U = (x + 0.5)/32 on a 32-texel texture
fetched texel x at every pixel (C, `Norm280`). The same mapping in texel
units wrapped (`Texel64`).

**The pitch field is a small float.** A sweep of 24 raw values (D,
columns 0 and 31) fits one rule:

    pitch bytes = (2m + 1) << (e + 2),   e = D[10:7], m = D[6:0]

| Field | Row pitch | Field | Row pitch |
|---|---|---|---|
| 080h | 8 B | 000h-07Fh, e.g. 001h | 12 B (2 + 4m words) |
| 180h | 32 B | 201h | 192 B |
| 280h | 128 B | 210h | 2112 B |
| 380h | 512 B | 2FFh | 32640 B |
| 400h | 1024 B | 040h | 516 B |

SiS's captured 280h (with 200h for level 1) is the tight pitch of a
64-texel ARGB4444 row and a 32-texel one.

**The engine ORs the row term into the column offset; it does not add.**
With an 8-byte pitch, row 1 column 31 fetched word 1Fh, not 23h. A pitch
whose lowest set bit is below the row's byte width therefore misaddresses.
A power-of-two texture at its tight pitch never does.

**Nearest is floor(u x W).** At four pixels per texel the columns run
0,0,0,0,1,1,1,1 from x = 0 (`Mag4`, triangle 1).

**U is not prestepped in x; V is prestepped in y.** The prestep triangle
used 8 texels per pixel across a 256-texel row:

| Model | Columns right (of 365) |
|---|---|
| U at the sample point | 0 |
| U at the exact left-edge crossing, stepped by dU/dx | **365** |

V was right on all 365 pixels. This is phase 2's Gouraud behaviour, now for
texture coordinates. It also explains `Mag4`'s 112 differing pixels: they
are all on triangle 2, whose diagonal starts 2/256 px left of its first
pixel. Samples placed exactly on texel edges there read one texel low.

**Wrap, mirror and clamp** match Direct3D's WRAP, MIRROR and CLAMP exactly,
with U running from texel -14.5 to 47.5 (F). With no mapping bit set,
every texel outside [0, 1) came back FFFFh.

**Perspective** (F, `Persp`: RHW 1.0 to 0.25 across x, U from 0.5/32 to
1 + 0.5/32):

| Model | Columns right (of 1024) |
|---|---|
| Direct3D: W is RHW, U unmultiplied, U x RHW and RHW linear in screen x | **1024** |
| affine | 32 |
| W as eye depth | 32 |

With perspective on and RHW constant, every pixel matched affine. With
perspective off, a varying W was ignored.

**Formats.** Hashed 32x32 textures through Ctex replace, with alpha test
GREATER 80h on the texel alpha. Expected values assume bit replication to
8 bits per channel:

| Format | Code | Colour mismatches | Alpha test wrong |
|---|---|---|---|
| RGB565 | 51h | 0 | 0 |
| ARGB1555 | 52h | 0 | 0 |
| ARGB4444 | 53h | 0 | 0 |
| RGB555 | 50h | 0 | 0 |
| ARGB8888 | 73h | 0 | 0 |

**Bilinear** (`LinearU`/`LinearV`, black/white alternating texels, 8
pixels per texel): red rose 0, 3, 7, 11 ... 31 from x = 4 to 12, peaking
at texel 1's centre. Texel centres sit at i + 0.5, Direct3D's convention.
Weights come in eighths at this scale, truncated, and edges clamp. U and V
behave identically.

**Texture-blend modes** (8A3Ch D[31:26]). One solid ARGB4444 texel (Atex
88h, Ctex FF/88/44) against vertex colour Cpix 40/FF/80. Run F used Apix
80h with mask bit 0; run G used Apix 40h with mask bit 7:

| Mode | Result | D3D |
|---|---|---|
| 0 | Ctex | DECAL, COPY |
| 1, 3, 5, 10, 11, 14, 15 | Cpix | - |
| 2 | Cpix x Ctex / 256, truncated (3C24h, exact) | MODULATE |
| 4 | (1 - Atex) Cpix + Atex Ctex (A5ECh, exact) | DECALALPHA |
| 6, 7 | Apix Cpix + (1 - Apix) Ctex (CD2Ah at Apix 40h, exact) | - |
| 8, 9 | Ctex if the selected Atex bit is 1, else Cpix | DECALMASK (bit 7) |
| 12, 13 | modulate if the selected Atex bit is 1, else Cpix | MODULATEMASK (bit 7) |

Bits D[31:30] change nothing: modes 16-63 repeat 0-15. The datasheet's
pairs, which print identically, give identical colour. Alpha output (8A3Ch
D[25:24]) was not measured.

**Mip levels.** A six-level chain, each level one marker colour. 8A38h
D[11:8] = 5, so the field is the last level's index, as SiS's field 1
with two pitches implies.

| Texels per pixel | 1 | 1.1 | 1.25 | 1.5 | 2 | 2.5 | 3 | 3.5-4 | 6-8 | 16 | 32 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| Level (most pixels) | 0 | 0 | 0 | 1 | 1 | 1 | 2 | 2 | 3 | 4 | 5 |

- **The level is round(log2 r)**, switching at 2^(n + 1/2).
- The larger axis rules: 4 in u and 1 in v gave level 2.
- **The level is chosen per pixel:** under perspective it stepped 0 to 4
  across a row.
- **Whole rows sometimes take one level higher.** At 1.5 to 2.5 texels per
  pixel, 5 to 9 rows of 32 did: at 2, rows 8-11 and 24-27. The rows depend
  on the ratio, not on x. Under perspective the patch is irregular.

**Blending between levels** (I, black/white alternating levels, so red =
weight):

| Code | 1.25 | 1.5 | 1.75 | 2.5 | 3 |
|---|---|---|---|---|---|
| 2 | level 0 | level 1 | level 1 | level 1 | level 2 |
| 3 | pure levels, 32-96 px of intermediates | | | | |
| 4 | 7/31 | 15/31 | 23/31 | 23/31 (white to black) | 15/31 |
| 5 | as 4, plus 32-96 px of other values | | | | |

Codes 4 and 5 blend floor(LOD) and floor(LOD) + 1. The LOD fraction comes
in quarter steps: 0.32 gives 1/4, 0.58 gives 1/2, 0.81 gives 3/4. Codes 2
and 3 do not blend between levels.

## What this settles

1. **The driver pulses 8A38h D4 on every texture change** (D4 set, then
   clear) and never draws with it set.
2. **The pitch encoding is the builder's `v9x_sis3d_texture_pitch_field`.**
   Textures use power-of-two tight pitches. The builder refuses a pitch
   the OR would misaddress.
3. **TLVERTEX texture coordinates go to the engine unchanged:** U and V
   unmultiplied, W = RHW, with 8A00h D9 set for perspective. Nearest
   sampling, bilinear centres and the three addressing modes are
   Direct3D's.
4. **All five Direct3D texture formats are exact:** RGB565, ARGB1555,
   ARGB4444, RGB555, ARGB8888.
5. **Texture-blend mapping.** DECAL/COPY uses mode 0, MODULATE mode 2 and
   DECALALPHA mode 4. DECALMASK and MODULATEMASK use modes 8 and 12 with
   mask bit 7, the alpha MSB. No mode adds.
6. **The mip level field is the last level's index; the level is
   round(log2) of the larger axis, per pixel.** Codes 4 and 5 give
   between-level blending at quarter-step weights.
7. **Texture coordinates, like colour, are not prestepped in x.** This is
   the hardware's behaviour; the error is under one pixel's worth of
   dU/dx per span, and the driver accepts it.

## Not established

- **What hung the engine in run A.** It was level field 0, D4 held set and
  a single texture write, together. Neither setting alone hung it after a
  pulse; the combination was not repeated.
- **Within-level filtering under codes 3 and 5.** The chains were solid
  per level, so bilinear within a level cannot show. Codes 3 and 5 left
  32-96 intermediate pixels, which this data does not explain.
- **The row-wise mip anomaly's cause.** Whether SiS's own HAL shows it on
  this card is untested; phase 4's V9XDDP comparison covers it.
- **Alpha output of the blend modes** (8A3Ch D[25:24]) and the
  MODULATEALPHA mapping that depends on it.
- **Bilinear weight precision beyond eighths.** Only an 8-pixels-per-texel
  ramp was measured.
- **Enable bit 15,** set in every scene as SiS sets it. Its effect was
  not isolated.
