# GT218 mipmaps: a 32 MiB tiled texture pool below the reserve, each chain copied there, and TIC word 7's level range; V9XD32 passes whole

Date: 2026-11-25. Machine: W9QI0DAD (AMD FX-6300, Windows 98 SE), ASUS
GeForce 210, GT218 `10DE:0A65`, `nvidia` package, desktop 1024x768x16,
boots 148-149. Plan:
[nvidia-gt218-mipmaps.md](../plans/nvidia-gt218-mipmaps.md).

## Before

The path advertised MIPNEAREST and MIPLINEAR but read level 0 of every
texture, since its textures are pitch-linear and an NV50 pitch TIC has
no levels. V9XD32 T21 (a 32x32 RGB565 chain of six levels, one colour a
level, drawn at four sizes) read red, level 0's colour, at all four.
`Failures` had counted that since at least 0.53.1. T21 wrote no result
line when it failed, so the failure had stayed hidden (it now writes
`T21Result` either way).

## The change

- **The pool** (`gt218_reserve.c`, `gt218_hw16.c`). The 16-bit reserve
  hook now ends the heap 32 MiB below the 2 MiB engine reserve when that
  leaves the screen whole (`v9x_gt218_heap_end`): `V9X_GT218_POOL_BYTES`,
  Michael's choice of size on 2026-11-25. The HAL finds the pool between
  `fb.vram_bytes` and `engine.reserve_offset`, and uses its whole
  row-block units only. It is outside the heap because DirectDraw
  rebuilds its heaps on a mode change, and a raw heap block would then be
  handed out under the copies.
- **Layout** (`v9x_nv50_d3d_mip_layout`, `nv50_d3d.c`), Mesa's
  `nv50_miptree.c` tiled layout: each level's pitch on the 64-byte GOB,
  its block height from `nv50_tex_choose_tile_dims` (the smallest of 4 to
  64 rows covering twice its height), levels back to back. T21's chain:
  modes 30h, 20h, 10h, 0, 0, 0; 4,352 bytes.
- **Records and copies** (`d3d_nv50.c`).
  - When a chain of two or more levels is placed, a record takes a
    first-fit block of the pool on the 512-byte tile.
  - Before a draw samples a chain created or written since, one 502D
    copy per level fills the pool, each level in its own tile mode, the
    same mechanism as the cubes
    ([2026-11-25-gt218-cube-maps.md](2026-11-25-gt218-cube-maps.md)).
  - The record is freed with level 0. A chain with no room samples
    level 0, as before.
- **TIC and TSC** (`v9x_nv50_d3d_tic_mip`; the map applies it when the
  stage's min filter is a mip filter):
  - TWO_D (4000h) block-linear with level 0's tile mode, last level in
    word 5 bits 31:28;
  - TSC mip filter nearest (80h) for MIPNEAREST and MIPLINEAR, linear
    (C0h) for the LINEARMIP pair, and the maximum LOD (levels - 1) in 4.8
    fixed point at word 2 bit 12;
  - **word 7 the view's level range, `last_level << 4`** (below).

Host tests: the heap end (`test_nv50_init.c`), the layout and TIC/TSC
(`test_nv50_d3d.c`), the map's choice by filter (`test_d3d_nv50_map.c`).
All but word 7's were written first and seen failing.

## First run: word 7

Boot 148: everything above, with TIC word 7 zero, as `nv50_tex.c` has it
for the NV50 class. The heap had shrunk by 32 MiB, as planned
(`T19AvailableTextureMem` 7C00000h to 5C00000h). T21 still read red at
all four sizes. For every class past NV50's, which includes the GT218's,
`nv50_tex.c` writes word 7 as the view's `(last_level << 4) |
first_level`. A zero there clamps the view to level 0, which fits what
T21 showed. The fix writes `last_level << 4`.

## Second run

Boot 149 (`run-release-checks.ps1`, 8 of 8 hashed; HAL SHA-256
`280CA321...`, `V9XDISP.DRV` `32E85CD6...`).

- **T21 passes:** levels 0 to 3 read red, green, blue and white
  (`T21Ok=F`). The hardware takes the smaller levels' block heights by
  the same rule as Mesa's layout.
- **V9XD32 `Failures=0`, `Result=PASS`**, the first clean V9XD32 on this
  card in the records. Every other verdict is the same as at boot 147.
- V9XGLP, V9XGLIDP, V9XR3DP, V9XWPRS and V9XFBCMP pass.

## Not measured

- **Levels 4 and 5** (2x2, 1x1): T21 draws four sizes.
- **Linear filtering between levels** (LINEARMIP*): T21 draws
  MIPNEAREST.
- **A game's mipmapped textures:** the pool's fill and the copies' cost
  under texture management.
- **The OpenGL ICD's textures,** which come through the explicit-draw
  levels and not this path.
- **What fills the pool first:** a 32 MiB pool holds the 32x32 test chain
  thousands of times over and a 256x256x32 chain about 90 times.
