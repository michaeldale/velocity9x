## What moved where

`rv515_3d.c` holds the R500 side the probe carried until now:
- the fixup of the RS690 builder's lists;
- the init's `R500_VAP_INDEX_OFFSET`;
- the R500 rasterizer setup;
- fragment programs from `r500_fp.c` for the colour state, the textured
  state, and the TL state's combine (REPLACE, MODULATE, ADD,
  DECALALPHA), texture alpha, specular and fog, in the RS690 TL
  shader's temp layout. The fog colour goes in as an R500 constant
  (IEEE singles, as Mesa writes them).

Two more fixup rules came in with it:
- drop the R300 shader constants (4C00h-4DFCh);
- OR `R500_FG_ALPHA_FUNC_8BIT` into an enabled alpha test, as Mesa does
  for an 8-bit target.

The probe now draws only through this module.

## Run 1: everything but fog

The first run passed 21 of 25 tests. TlFogFull, TexFogFull, TlFog and
TlFogSpecular mismatched:
- TlFogFull (f = 0, so the output should be the fog colour) came out as
  the unfogged diffuse red (`F800` where `001F` was expected).
- TexFogFull came out as the unfogged texel.

So f read as 1. TlSpecularOnly passed, so the specular colour did reach
its temp.

The cause: as on the R300, an R500 RGB operand's A swizzle (AAA) reads
the alpha unit's source slot, not the RGB unit's. Mesa's pair compiler
routes W reads the same way. The fog step read f through RGB slot 2,
which named the specular temp. Alpha slot 2 still named temp 0, the
diffuse with alpha FFh, so f was 1. DECALALPHA's AAA step had passed only
because both of its slots named temp 0.

Fix: name the same temp in the alpha slot (fog's f, and explicitly for
DECALALPHA's texel alpha). The host test now checks it.

## What it settles

The R300-class state the RS690 builder writes works on the R500 for Z16,
blending, culling, scissor, channel masks and perspective-correct
texturing. With the fixup and R500 programs, every TL-state feature the
RS690's Direct3D HAL uses has now drawn correctly on the X1300. The
exceptions are colour key, mipmaps and the other texture formats, which
the probe does not run yet.

Not run on silicon: the encoder's TEXKILL, and any program over four ALU
steps.
