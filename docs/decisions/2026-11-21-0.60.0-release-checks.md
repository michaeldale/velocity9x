## What changed since 0.59.0

Every probe verdict compared with `0.59.0-release-checks-2026-11-20`, by machine and check.

- **i5-4570, HD 4600**: not in the 0.59.0 checks; nothing to compare.
- **Netbook, GMA 950**: no verdict changed.
- **M-KYHT4Q, GM965 GMA X3100, TOMMOHP (remote help)**: no verdict changed.
  - V9XSNA new: LastExit 0x00000000
- **M-XP7053, Radeon R7E Carrizo (remote help)**: no verdict changed.
  - V9XSNA new: LastExit 0x00000000
- **M-5CAPM3, Radeon X1300 RV515 (remote help)**: not in the 0.59.0 checks; nothing to compare.
- **M-NZHWBR, i3-2105 HD 3000 Sandy Bridge (remote help)**:
  - V9XD32 bpp16 not run this time
  - V9XSNA new: LastExit 0x00000000
  - Not caused by 0.60.0. The machine list changed: 0.58.0 and 0.59.0
    ran the HD 3000 from a scratch list whose entry asked for `/bpp16`;
    this run used the new `hd3000` entry in the private list, which asks
    for the default, `/ddi6` and `/ddi5` runs, all PASS. The V9XSNA line
    is the snapshot reading its exit code again now that the driver and
    probe share an ABI (0.59.0 read it as absent after its ABI bump).
- **M-5CAPM3, Radeon X1300 RV515**, first release check: every probe
  passes, V9XD32 at 32 and 16 bpp with no failures, on the package with
  the day's X1300 work (`b3996f07`).
