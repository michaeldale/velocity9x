# No refresh rate can be chosen on VBE mode sets

Date: 2026-11-06. Feature gap, found in a feature review. Status: open,
nothing written for the driver; the block builder exists and is
host-tested.

## Gap

Every DirectDraw mode row publishes refresh 0, "the default"
(`src/display16/dd16.c`), and every VBE mode set takes the BIOS's timing.
`src/common/vbe_crtc.c` builds a VBE 3.0 CRTCInfoBlock from an EDID
detailed timing and is pinned by `tests/host/test_vbe_crtc.c`, but nothing
in the driver calls it.

## Feature

On a VBE 3.0 BIOS that reports CRTC support:

1. the monitor's native timing from EDID on its native mode;
2. a chosen refresh (for example 60, 72, 75, 85 Hz) on other modes, with
   timings generated by VESA CVT, or CVT reduced blanking for digital
   panels, and limited by the EDID range descriptor;
3. the choice on the settings page, and the rates published per mode so
   Display Properties and DirectDraw can ask for them.

CVT generation and the EDID limit check are pure arithmetic for the host
suite. The settings page needs a way back if the monitor loses sync.

## Acceptance

On one VBE 3.0 machine with a CRT or EDID monitor, a mode set at a chosen
rate, with the monitor's own on-screen display reporting it, and a host
test pinning the CVT output against the VESA spreadsheet values.
