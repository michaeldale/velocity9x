# AMD Mullins (Radeon R3E, GCN 2) in the ati family

Date: 2026-11-08

Status: Phases 0-5 done on M-JJN1ZZ (boot 14, `8e80796e`,
[record](../decisions/2026-11-08-mullins-directdraw-on-sdma.md)); one
`CANBLT` busy answer in four V9XDDP runs is open. Next: Phase 6, the GFX7
CP.

Target: the GPU in AMD's GX-412HC embedded APU, PCI `1002:9854` rev 01,
subsystem `1002:9854`, which Linux binds as `CHIP_MULLINS` (9850-985F), a
CIK ("Sea Islands") part: GFX7, SDMA 2, DCE 8.3. Test machine: M-JJN1ZZ
(`W9QI0DA2`), remote help, reached only over the relay.

The approach is the one [Carrizo's plan](ati-carrizo-gfx8.md) took, and
most of Carrizo's code carries over: Linux's CIK and VI register headers
put SDMA, the MC, GRBM/SRBM, the CP ring registers and the first display
controller at the same offsets
([register record](../decisions/2026-11-08-mullins-register-probe.md)).
What differs is the microcode, a few golden values, the RLC and CP
microcode ports (C300h and C150h, not 3B000h and 3E050h), the SMU, and the
shader ISA.

## Sources

`build\external\carrizo\linux\` (outside version control) gained, by
sparse checkout of the same `torvalds/linux` commit: `amdgpu/{cik,cik_sdma,
gfx_v7_0,gmc_v7_0,cik_ih}.c`, `cikd.h`, `cik_sdma.h`, and the register
headers `gca/gfx_7_2_*`, `oss/oss_2_0_*`, `gmc/gmc_7_1_*`, `dce/dce_8_0_*`,
`bif/bif_4_1_d.h`, `smu/smu_7_0_1_*`. Microcode in
`build\external\mullins\firmware\`: linux-firmware's
`amdgpu/mullins_{sdma,sdma1,pfp,me,ce,rlc,mec}.bin`, under
`LICENSE.amdgpu` (the same file and hash as Carrizo's).

## Phases

0. **Baseline (done).** `vbe` since boot 9, write-combining A/B on boots
   10/11 (2026-11-07).
1. **Identity (coded).** `src\chipsets\ati\cik\mullins_hw16.c`, a row in
   the `ati` manifest for `1002:9854` with no subsystem id. The family's
   PCI id table grew to 48 for its 41st id.
2. **Read-only register probe (done).** `V9XCKMM`: 256 MiB carve-out at
   GPU `F4_00000000` behind a 256 MiB BAR0, VBE scanout at its start,
   every engine halted with no microcode, GFX powered, power gating off.
3. **SDMA write probe (done).** `V9XCKDMA`: microcode through the port,
   ring test, copies and fills byte-exact
   ([record](../decisions/2026-11-08-mullins-sdma-write-probe.md)).
4. **DirectDraw on SDMA (coded, not booted).** Carrizo's engine
   (`engines\eng_vi.c`) with `V9X_DD_ENGINE_CAP_VI_MULLINS`: Mullins'
   microcode (`cik\cik_sdma_microcode.c`, generated by
   `scripts\gen-mullins-microcode.ps1`), CIK's golden values, no doorbell.
   Done means V9XDDP passes at 16 and 32 bpp with the engine claimed, and
   the counters show the blits on it.
5. **Flips.** Claimed with Phase 4 through `eg_scanout.c` (DCE 8's first
   controller is at Evergreen's offsets). Done means flips confirmed by
   the chip in V9XDDP and a game run.
6. **CP and 3D (GFX7), its own plan when started.** RLC and PFP/ME/CE
   microcode through CIK's ports, a ring test, `gfx_v7_0` gpu_init and the
   CIK clear state, then the shaders. The ISA is GCN 2 (Sea Islands):
   scalar memory is SMRD rather than GCN 3's SMEM, and the VOP3 and some
   opcode encodings differ, so `vi_shader.c`'s encoder needs a GFX7 mode
   checked against AMD's *Sea Islands Series Instruction Set Architecture*
   reference (not yet downloaded).

## Unknowns that need a measurement

- Whether this BIOS lists 8 bpp modes (the row hides any it does not).
- Whether the mode-change restart of SDMA holds on Mullins as it did on
  Carrizo (the probe ran once).
- The SMU's state, never read: CIK's microcode does not go through it.
